## 3. 已确认可用的技术选择

- **自适应采样 + BIN_V1**：不进数据库就能满足体积预算，落盘与回放共用同一模型。
- **航路优先级 AIP → 图 → SimBrief**：三级链路与失败原因（`no_match` / `detour_too_large` / `requires_online`）都能对外解释，前端可按 `provider + warnings` 出提示。
- **MapLibre 增量 `setData`**：不需要分块渲染或 Canvas 自绘，10k 点在全量重绘下仍是 26.7ms。
- **服务端 Session + 双提交 CSRF**：V-09 的 16 项（含伪造 CSRF、越权写、`min_fl > max_fl`）全部按预期拒绝。
- **ack 文件 + 主键幂等**：崩溃恢复不需要分布式事务，重复批次靠 `INSERT OR IGNORE` 去重。
- **单文件 HTML 报告（内联 SVG）**：`report.html` 用遥测卡片 + ALT/V-S/G 曲线 + 跑道接地区俯视图直接呈现一次落地，零外部依赖、可离线分发给飞行员看；后续接前端时图表逻辑可平移到 React。

## 4. M0 暴露的问题（M1 前必修）

1. **跨洋图航路绕行 2.07 倍**：EGLL→KJFK 出图 6203.5 NM，大圆仅 2991 NM，且置信度 `high`、覆盖检查 PASS。已加 `MAX_DETOUR_RATIO=1.6` 拦截，改为 `REQUIRES_SIMBRIEF`；M1 还需按航路长度分档（远程 1.25×）并识别 NAT/PACOTS 轨道。
2. **navdata `airway` 表存在 min>max 脏区间**：Y803 为 25000/24500，若直接比较会误判。已按未知处理；M1 上线前要扫描全库统计脏区间比例。
3. **network.pkl 的边没有 min/max FL，且边端点 ident 与 navdata 航段表不对齐**：按 `edge_airway` 反查 22 段全部落空。已改为从航路串还原 `(航路, 起点, 终点)` 再查 navdata，ZBAA→ZSSS 命中 18/19 段。M1 应在建图时就把 `min_fl/max_fl` 写进边。
4. **高度校验曾"空校验通过"**：`checked=0` 时返回 `valid=true`，等于没校验。已改为 `valid=null` + `altitude_unverified` 警告；前端必须把"未校验"和"校验通过"分开展示。
5. **生成成功的航路缺 `simbrief_url`**：只有 deferred 分支带链接，违反 D-20。已在 `generate()` 统一补齐。
6. **心跳 1s 判定过于激进**：本机测试可用，生产应 3–5s，并校验 `seq` 单调性，避免旧心跳覆盖新状态。

### 4.1 已修：SimConnect 实机联调暴露的问题

1. **1 Hz 抽稀在断流后会"追写"**：`nextWrite` 落后于当前时间时每帧都通过阈值，实测 2.4 s 内灌进 112 条样本。改为 `nextWrite = t + 1/hz`。
2. **`CHANGED` 采样 + 暂停会造出假事件**：停机位静置 110 s 无帧，恢复时飞机已在 3195 ft，被判成 `liftoff`。已加"相邻帧间隔 >3 s 不做起降转换判定"守卫，回放侧同步。
3. **`PLANE PITCH DEGREES` 是低头为正**：直接落盘会把"抬头 5.8°"记成 −5.8°。采集侧取负，统一为抬头为正（`flight.jsonl` / `touchdowns.json` 同口径）。
4. **G 只取触地首帧会低估**：首帧 0.98 vs 工具 1.39。改为触地后 2 s 窗口取帧级峰值 `g_force_peak`，瞬时值保留在 `g_force`。
5. **载入瞬间脏样本**：`t≈0` 出现 AGL 53,803 ft / G=0，`t≈22` VS 恒定 6250 fpm，按 min/max 绘图会把曲线压成直线。报告改用 2%~98% 分位裁剪，原始数据不删。
6. **跑道几何只有入口单点**：`runways.csv` 无长度/宽度，跑道长度由反向记录（36R↔18L）两点反推，宽度缺失故横向图固定 ±20 m 窗口；缺反向记录的机场拿不到长度，面板自动跳过。

```powershell
python -X utf8 spikes\track_sampling_probe\probe.py       # V-03

cd spikes\tauri_map_probe; npm.cmd install; npm.cmd run build; python -X utf8 fps_probe.py   # V-07
```

## 7. 限制说明

- SimConnect 结论已来自**真实 MSFS 飞行**（本机 SimConnect 12.2，两次 ZSSS 36R 进近着陆，A321 / A330-300 RR）。仍缺：单次 ≥10 分钟连续采集（最长 458 s）、MSFS 2024 与更多机型/机模覆盖；`dropped` 计数未实现。
- 落地指标只与**一个**第三方落地评分工具（截图取值）对照，未做多工具交叉；接地纵向距离（距入口米数）无第三方参照，靠 `runways.csv` 入口坐标 + 真航向自算。
- 跑道数据只有入口坐标 + 航向 + 标高：长度由反向跑道记录反推，宽度缺失，接地区/瞄准点标记按标准 300/600/900 m 等距绘制，未核对具体机场的道面实况。
- 航路 AIP 层使用 **fixture CSV**（`data/aip_routes_sample.csv`），仅验证优先级与校验逻辑，不代表真实 AIP 数据。
- Volanta 未登录，`/api/v1/Flights` 未真实调用；CSV 兜底与诊断文案已验证。
- 相机/帧率测试为无头 Chrome 软渲染，硬件 GPU 环境预期更高；未测 4G 内存/低端核显。
- V-08 当时只出了**便携包**（浏览器 + 本地 Python 静态服务），未产出 MSI/NSIS：打包机缺 Rust 与 MSVC。**已在 M1 补齐**：装上 Rust（MSVC ABI）与 VS 2022 Build Tools 后产出 NSIS/MSI，Tauri release 可拉起 `aoc-core` + SimLink 三进程；仍未验证的是干净机安装/卸载、WebView2 bootstrapper 与后端崩溃自动重启（见 [08-便携包与测试清单.md](08-便携包与测试清单.md) T-05/T-06）。

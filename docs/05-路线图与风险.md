# 05 路线图与风险

> 版本 v0.1 · 状态：建议方案（待评审）

## 1. 里程碑总览

假设 1–2 名开发者、以业余时间为主；工期是**相对估算**，不是承诺。每个里程碑都有可演示的出口标准，避免「做了很多但没有一样能用」。

| 里程碑 | 目标 | 预估 | 出口标准 |
|---|---|---|---|
| M0 技术验证 | 把高风险点打通 | 2–3 周 | C# SimLink 能稳定采到轨迹/过载/接地点；Volanta 能同步；航路引擎能按 AIP/覆盖/图分级；Tauri + React 地图能画 1 万点；三进程能互相拉起 |
| M1 个人模式 MVP | 单机能完成「推荐→航路→飞→记录→回看」 | 6–8 周 | 验收 A-01 ~ A-04、A-21 ~ A-26、A-30 全过；可打包便携 ZIP 与 Tauri NSIS/MSI（**已完成**，见 [09](09-M1交付说明.md)） |
| M2 单机运营模式 | 一个应用内跑通「机队 → 航线/班期 → 抽班/自由飞 → 配载 → 结算 → 账本」+ 应用内规则配置 + 异常结算策略；无服务端 | 6–8 周 | 验收 A-05 ~ A-08、A-14 ~ A-19、A-27 ~ A-29 全过；无网络、无服务端可完整跑通（**已完成**，见 [10](10-M2交付说明.md)） |
| M3 联机模式 | 服务端 + 多客户端 + 账号/公司/角色/邀请码 + 网页管理端 SPA + 并发锁/离线补传/权限 | 6–8 周 | 验收 A-09 ~ A-13、A-20 全过；2 个客户端并发抽班不冲突 |
| M4 打磨 | 统计、回放、管理端、性能、发布 | 持续 | 可对外测试；崩溃率/上传成功率达标 |

> M2 不部署任何服务端：不建账号、公司、角色、邀请码，也没有 `apps/server` 与 `apps/admin-web`；数据与规则都在本机 SQLite，管理入口是客户端内的页面。M1 已有的 `aoc-core` 本地 sidecar 是应用内部进程（`127.0.0.1` + 随机端口 + token），不属于服务端。服务端、账号体系、网页管理端、并发与权限整体顺延到 M3。

### 2.1 验证清单

| # | 验证项 | 方法 | 通过标准 | 失败退路 |
|---|---|---|---|---|

## 3. M1 个人模式 MVP

### 3.1 范围

- 客户端外壳：Tauri 2 + React 19 + TypeScript；导航、主题、设置；`aoc-core` 负责本地 DB/迁移，通过本地 HTTP sidecar 提供数据。
- 个人模式页面：推荐、航路、飞行日志、轨迹回放、统计、设置。
- SimLink（C#/.NET 8）：连接、内部采样、自适应分段落盘、自动起降、落地指标、本地队列。
- Volanta：API + CSV + 手动补录。
- 航路：AIP 优先 → 覆盖检查（无高空航路转 SimBrief）→ Pre-train 图；SID/STAR 候选 + `.pln` 导出。
- 打包与首次运行向导。

### 3.2 不做

- 不做运营模式入口（可留灰显）。
- 不做天气/备降/油量精细规划。
- 不做 X-Plane。
- 不做云同步。

### 3.3 出口标准

- A-01 ~ A-04、A-21 ~ A-26、A-30 全过。
- 干净 Windows 机器安装后 10 分钟内能完成一次「推荐→航路→飞行→记录」。
- 连续 3 小时飞行不丢点、不崩溃。
- 轨迹文件可导出 GPX，第三方工具能打开。

> 实施状态（2026-10-20）：M1 代码、便携 ZIP 与 Tauri NSIS 安装包均已完成，验收证据与已知限制见 [09-M1交付说明.md](09-M1交付说明.md)；安装包仍依赖系统 Python（后续打 sidecar）。

- 有个问题：随机机场时，某些机场的跑道长度不对

## 4. M2 单机运营模式（无服务端）

### 4.1 形态

```
AOC 客户端（Tauri + React）
  ├─ aoc-core（Python sidecar，本地 HTTP + SQLite）  ← 业务与数据的唯一权威
  └─ aoc-simlink（C#，SimConnect 遥测）
```

- **只有一个应用**：安装后直接打开即用，不需要启动服务端、不需要 Docker/PostgreSQL、不需要联网。
- **没有账号体系**：不登录、无会话/密码/CSRF；无角色（ADMIN/PILOT/DISPATCHER）、无邀请码、无权限校验。
- **没有公司实体**：不做多公司、不做 `company_id` 多租户隔离，也没有「加入/创建公司」流程。
- 只有一个**本机档案**：航司名、ICAO/呼号前缀、基地、货币、单位、主题；首次运行向导里填写，之后随时可改。
- 数据全在本机 SQLite：单文件 + WAL + 每日备份 + 档案 zip 导出/导入。
- **单实例锁**：同一时刻只允许一个实例写库，避免两个窗口重复占用同一架飞机。
- 本地 sidecar 仍是应用内部进程（`127.0.0.1` + 随机端口 + 一次性 token），不对外监听、不是可部署的服务端。

### 4.2 范围

- 机队：机型模板 + 逐机档案（注册号/构型/客舱/小时/循环/当前位置/状态）+ 导入导出。
- 航线/班期/航班实例：应用内维护航线，按班期模板本地生成未来 N 天航班实例。
- 抽班、重抽、锁定、自由飞行：本地事务 + 唯一索引保证同一架飞机只有一个 `HELD/IN_FLIGHT`；重抽无冷却/费用/次数。
- 配载生成、结算、账本：本地计算并落库；收入/成本明细可逐班对账。
- **经济参数与异常策略**：应用内「运营规则」页配置，草稿 → 预览 → 发布 → 版本回滚；发布写本地审计（操作人固定为本机档案）。
- **异常与结算策略**：`ACCEPT` / `REJECT` / `WEIGHTED` / `REVIEW`；`reject_cost_mode`、`review_advance_ratio`、`scope_mode`（默认/机型/单机）；`HELD` 进入应用内「复核队列」，本人确认后写 `settlement` + `ledger`。
- 应用内管理页：机队、航点/航线、班期、经济参数、异常策略、复核队列、审计、备份/还原、重置。
- 飞行链路复用 M1：SimLink 采集 → 本地队列 → aoc-core 落地评估与结算，不新增上传环节。

### 4.3 不做（顺延到 M3）

- `apps/server`（FastAPI + PostgreSQL + Alembic + Docker Compose）与任何 `/api/v1` 服务端接口。
- 账号、登录、会话、密码、CSRF；角色、邀请码。
- 公司实体、多公司、多租户 `company_id`。
- `apps/admin-web` 网页管理端 SPA 与 `/admin` 路由。
- 多客户端、并发锁、`GET /sync` 轮询、在线状态、离线 outbox 与补传。
- 服务端审计、HMAC 遥测签名、限流、封禁、IP 白名单。
- 多人 CPDLC 上行报文（依赖账号与在线机组）。

### 4.4 出口标准

- A-05 ~ A-08、A-14 ~ A-19、A-27 ~ A-29 全过，且**全程无服务端、可断网**。
- 新机器安装后不登录、不起服务，30 分钟内从建机队/航线到完成 10 个航班，账本能对上。
- 应用内改经济/异常参数后下一班生效，历史结算不变；可回滚上一版本，审计可追溯。
- 单实例：重复启动或并发写库被阻止/明确提示，同一架飞机不会被两班同时占用。
- 运行中只有客户端 + `aoc-core` + SimLink 三个进程，无端口冲突；拔掉网线不影响全流程。

## 5. M3 联机模式（服务端 / 账号 / 管理端）

### 5.1 范围

- `aoc-server`：FastAPI + PostgreSQL 16 + Alembic，Docker Compose 一键起；`/api/v1` 与 `/api/v1/admin/*` 只返回 JSON。
- 账号、登录、会话、CSRF、密码策略；公司、角色（ADMIN/PILOT，P1 DISPATCHER）、邀请码、多租户隔离。
- 客户端接服务端：机队/航班/抽班/配载/结算以服务端为权威，本地缓存 + outbox。
- **网页管理端 SPA**（`apps/admin-web`，React + TypeScript + Vite）：登录、公司档案、经济参数、机队、航点/航路、航线/班期、用户、审计、复核。
- 轮询同步（`GET /sync`）、在线状态、飞机位置（定时 POST/GET）。
- 离线 outbox、断线补传、锁心跳与过期、并发锁。
- 服务端遥测校验与 `SUSPECT` 复核流程。
- 权限细化、服务端审计、限流、HMAC 签名、IP 白名单。
- 多人 CPDLC 上行报文（Hoppie 优先，客户端通知降级）。
- 部署文档、备份/恢复、升级流程。

### 5.2 从 M2 迁移

- M2 的本机数据（机队/航线/班期/结算/账本/规则版本）提供一次性导入：建默认公司与 ADMIN 账号，保留原 ID 与时间戳。
- 规则版本与审计随导入保留；此后服务端为权威，客户端本地库降级为缓存。

### 5.3 出口标准

- A-09 ~ A-13、A-20 全过。
- 2 个客户端同时抽班/自由飞不冲突，只有一个成功。
- 断网 20 分钟飞行，恢复后轨迹连续、结算正确。
- 服务端重启后，锁与在飞航班可恢复（或安全回收）。
- 管理员在网页端改参数后，下一班生效，历史结算不变；审计可追溯。
- 飞行员账号访问 `/api/v1/admin/*` 返回 403；SPA 直接访问 `/admin/economy` 只加载页面、不拿到数据；缺失 CSRF 的写请求被拒绝。

## 6. M4 打磨（按优先级）

1. 轨迹回放体验：时间轴、高度/速度曲线、事件跳转。
2. 统计与成就：机场收集、机型徽章、月度报告。
3. 天气/备降/油量：METAR/TAF、跑道风、备降建议。
4. 管理端体验优化：批量导入、参数预览/回滚、移动端查看。
5. 多公司/排行榜（若要做联机社区）。
6. 其他模拟器适配（不在当前范围；如未来扩展再换 SimLink 适配层）。
7. VATSIM/IVAO 在线状态（只读，不替代客户端）。
8. 自动更新、崩溃上报、遥测（匿名，默认关）。

## 7. 风险

| # | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| R-01 | Volanta 私有 API 失效/改版 | 高 | 个人模式历史数据缺失 | CSV/手动兜底；本地日志为权威；UI 明确提示 |

| R-18 | 覆盖/预付款组合复杂，结算口径争议 | 中 | 客服/信任成本 | 生效预览显示来源；快照固化；复核页展示计算明细；覆盖优先级写死并测试 |

| R-20 | 覆盖检查误判（漏判低空/误判终端区） | 中 | 错误 SimBrief 或错误放行 | 忽略起降 50NM；短程跳过；AIP 优先；固定航线样本回归；保留 `force_graph` 高级开关 |
| R-21 | 轮询请求量过大/同步延迟 | 中 | 服务端压力/操作延迟 | 飞行 5s、空闲 15–30s；增量 cursor；失败退避；P2 再评估 WebSocket |
| R-22 | 公务机/特殊构型套用干线经济模型导致亏损或刷钱 | 中 | 机型不可用/经济失真 | `role` + `cabin_config` + `demand_profile` 分支；BIZJET 走包机费；`allow_scheduled` 默认关；预览验证 |
| R-23 | Tauri + Python sidecar + C# SimLink 三进程启动/端口/打包失败 | 高 | 客户端无法启动/遥测丢失 | 随机端口 + token + 握手文件；健康检查/自动重启；V-08/V-10 先验证；提供独立安装器退路 |
| R-24 | M2 单机运营缺少服务端约束，参数/结算可被本地改库绕过 | 中 | 经济失真/无成就感 | 单实例锁 + 参数版本化 + 审计；本地改库视为用户自选作弊，不做对抗；M3 起服务端权威 |

# 06 网页管理端（Web Admin）

> 版本 v0.1 · 状态：新增需求（已确认要网页端）
>
> 里程碑：本文对应 **M3 联机模式**。M2 单机运营模式没有网页管理端，也没有账号/角色/邀请码；机队、航线、班期、经济参数、异常策略、复核与审计都在客户端应用内完成（见 [05-路线图与风险.md](05-路线图与风险.md) §4）。
>
> 目标：联机模式下，管理员通过浏览器修改公司、经济、机队、航点、航线、班期、用户等参数，不依赖桌面客户端。

## 1. 定位与范围

### 1.1 是什么

- 公司模式的**管理后台**，面向 `ADMIN`（P1 起支持 `DISPATCHER`）。
- 与桌面客户端共用同一个 `aoc-server`、同一套 service 层与数据库。
- 浏览器加载独立 SPA（`/admin` 路由），通过 `/api/v1/admin/*` 读写数据；**渲染由客户端完成，服务端只提供 JSON**。

### 1.2 不是什么

- 不是玩家端：飞行员仍用桌面客户端抽班、飞行、看结算。
- 不是公开门户：没有公开注册、公司介绍、排行榜；只有登录后的内部管理。
- 不是全功能 CMS：不管理公告文章、图片、主题等非运行数据。
- 不是服务端渲染应用：不使用 Jinja2/HTMX/SSR，不返回 HTML 页面。
- MVP 不做跨公司超级管理员（一个服务端一家公司）。

### 1.3 「公司相关参数」的范围

| 分组 | 包含 | 谁能改 |
|---|---|---|
| 公司档案 | 名称、ICAO、呼号前缀、基地、货币、初始资金、时区显示 | ADMIN |
| 经济参数 | 需求、票价、货运、成本、惩罚、保险、经济防刷 | ADMIN |
| 机队 | 机型模板、单机档案、引进方式、成本、当前位置、状态 | ADMIN |
| 航点/导航 | 自定义航点、公司航路、navdata 版本与导入 | ADMIN |
| 航线/班期 | 航线、班期模板、航班号规则、航班实例生成 | ADMIN（P1 签派） |
| 用户 | 邀请码、角色、禁用、重置密码 | ADMIN |
| 运行 | 航班监控、强制释放锁、异常复核 | ADMIN（P1 签派） |
| 异常与结算 | 数据缺口/加速/暂停/瞬移动作、阈值、折算、成本模式、预付款、覆盖、复核 | ADMIN 改；DISPATCHER 复核 |
| 审计 | 配置变更、登录、危险操作 | ADMIN 只读 |

> 服务器级参数（数据库连接、TLS、端口、备份路径）不在网页端修改，走部署配置/环境变量，避免把运维权限暴露给业务管理员。

## 2. 技术方案

### 2.1 客户端渲染 SPA

| 层 | 选择 | 理由 |
|---|---|---|
| 前端框架 | **React 19 + TypeScript** | 表格/表单密集；组件生态成熟；与 API 解耦 |
| 构建 | **Vite** | 冷启动快、代码分割、静态产物简单 |
| 路由 | React Router | 前端路由；服务端只做 history fallback |
| UI | Ant Design 5 | 表格、表单、弹窗、日期选择开箱即用 |
| 数据请求 | TanStack Query + fetch/axios | 缓存、重试、加载/错误状态 |
| 表单/校验 | Ant Design Form + Zod | 客户端即时校验；服务端 Pydantic 再校验 |
| 图表 | ECharts / Chart.js | 概览、参数预览分布 |
| 认证 | HttpOnly Session Cookie + CSRF Token | 浏览器端不接触 token；与桌面端 Bearer 分离 |
| 部署 | Nginx/CDN 静态文件；开发用 Vite dev server | 前端与 API 独立部署/扩容 |

**渲染方式**：按要求采用客户端渲染（CSR）；服务端只提供 `/api/v1/admin/*` JSON，不返回 HTML、不做模板/SSR，不使用 Jinja2/HTMX。前端是独立静态产物，可部署在 Nginx/CDN，也可与 API 同域。

### 2.2 与 API 的关系

```
浏览器（admin-web SPA）
  │ 静态资源：Nginx / CDN
  │ JSON：fetch/axios + Cookie
  ▼
FastAPI（只提供 JSON，不渲染 HTML）
  ├─ /api/v1/admin/auth/*      登录 / 登出 / me
  ├─ /api/v1/admin/*           业务数据
  ├─ 调用同一 service 层（不重复业务逻辑）
  └─ 写 company_config_version / history / audit_log

桌面客户端 ──HTTPS──► /api/v1（Bearer token，JSON）
```

- 业务规则只在 service 层实现一次；Web 与 API 都是入口。
- Web 端不做「绕过校验直接写库」；所有写入走 service。
- Web 与 API 统一返回 JSON 错误；前端负责把字段错误映射到表单。
- 前后端分离部署时配置 CORS 白名单；同域部署则不需要跨域。

  └─ /import                   navdata 导入/版本
/admin/network                 航线与班期

## 4. 页面规格

### 4.1 登录 `/admin/login`

- 用户名 + 密码；错误提示不区分「用户不存在/密码错误」。
- 登录成功写审计；失败按 IP + 用户名限流（5 次/5 分钟）。
- 服务端设置会话 Cookie：`HttpOnly`、`Secure`、`SameSite=Lax`；空闲 30min 过期，绝对 12h；响应返回 CSRF token，SPA 存内存并用于后续写请求。
- 可选：管理员 IP 白名单/VPN（部署配置）。
- 不做公开注册；账号由 ADMIN 创建或邀请码加入。

### 4.2 概览 `/admin`

- 卡片：公司余额、今日收入、今日成本、今日利润、在飞航班、在线飞行员、待复核航班、锁定飞机数。
- 列表：最近 10 个航班、最近 10 条审计、待处理通知。
- 快捷入口：改经济参数、加飞机、排班期、生成航班。
- 数据每 10s 轮询（TanStack Query `refetchInterval`），MVP 不做 WebSocket。

### 4.3 公司档案 `/admin/company`

字段：名称、ICAO、呼号前缀、基地机场、货币、初始资金、时区显示、公司简介（可选）。

- ICAO/呼号前缀唯一；修改呼号前缀影响后续航班，不改历史。
- 基地机场变更需二次确认；只影响新抽班/新航班，不搬已有飞机。
- 初始资金只允许「调整」并填写原因，写审计；不允许清零。
- 货币创建后只读（MVP 不做汇率）。

### 4.4 经济参数 `/admin/economy`

按 5 个 Tab 分组，字段带单位、默认值、范围、公式说明。

| Tab | 关键参数 |
|---|---|
| 需求与载客 | 机场需求权重、距离衰减、时段/星期/季节系数、随机波动、载客率上限、两舱比例、货物生成 |
| 票价与收入 | 经济/商务/头等基础价与每海里价、机场等级系数、货运/邮件单价、附加服务 |
| 成本 | 燃油单价（含机场覆盖）、起降费/吨、地面服务/客/货、机组/小时、维护/小时+循环、租赁/小时、停机/小时、空管/海里、保险比例 |
| 惩罚与保险 | 失约、取消、提前结束、备降、坠机、修理、保险赔付 |
| 经济防刷 | 同航线重复衰减、最低 block time（异常处置见 `/admin/policies/settlement`） |

每个字段：

- 显示当前值、默认值、单位、取值范围、帮助文本（含公式）。
- 失焦即校验；错误就地显示，不提交。
- 支持「恢复默认」（单字段/整组）。
- 顶部显示当前配置版本、最后修改人、时间。

页面底部操作：

| 按钮 | 行为 |
|---|---|
| 保存草稿 | 仅保存在浏览器 localStorage，不影响运行，不跨设备 |
| 预览影响 | 用当前表单值跑 100 班合成航班，返回利润分布、载客率、破产概率 |
| 发布 | 校验 + 乐观锁 + 写新版本 + 审计；高危参数必填原因；下一班生效 |
| 版本历史 | 查看/对比/回滚到任一历史版本 |
| 导入/导出 | JSON 导入导出，便于备份与批量改 |

### 4.5 机队 `/admin/fleet`

**机型模板 `/types`**

- 列表：ICAO、variant、名称、role、座位/客舱构型、货舱、MTOW、航程、油耗、最小跑道。
- 新建/编辑：字段见 03 文档 `aircraft_type`；唯一键 `(icao, variant)`；可配 `role`、`cabin_config`、`demand_profile`、`allow_scheduled`、`allow_charter`、`charter_rate_per_hour`、`fare_multiplier`；载客合计由 `cabin_config` 自动求和。
- `BIZJET/VIP` 可复制 A340-300 模板后改 `variant=BIZJET` 与客舱构型，不影响普通 A340-300。
- 可从内置模板复制；不允许删除已被飞机引用的机型（只能停用）。

**单机档案 `/aircraft`**

- 列表：注册号、机型、当前位置、状态、总小时、油量、所属基地。
- 新建：注册号、机型、基地、引进方式、成本、初始位置、初始油量。
- 编辑：涂装、基地、租赁/折旧成本、状态。
- 危险操作：修改当前位置（需原因，写审计）、强制释放锁、送修/退役。
- 校验：注册号唯一；机型存在；基地机场存在；MTOW 与最短跑道警告。

### 4.6 航点与导航 `/admin/nav`

**自定义航点 `/waypoints`**

- 列表/搜索：ident、类型、坐标、备注。
- 新建/编辑：ident 唯一、经纬度合法、类型（FIX/VOR/NDB/机场/自定义）。
- 与 navdata 冲突时警告，不阻止（允许覆盖公司内部习惯命名）。

**公司航路 `/routes`**

- 列表：dep/arr、航路串、SID/STAR、巡航高度、最低机型。
- 新建：可从航路引擎生成后保存；支持粘贴航路串校验。
- 校验：机场存在、航路串合法（调用 `aoc-route`）、距离/高度合理。

**navdata `/import`**

- 显示当前 AIRAC、生效日期、校验和、导入时间。
- 上传 SQLite/CSV；异步任务 + 进度；导入前备份；失败回滚。
- 导入后校验 `network.pkl` 的 AIRAC 是否一致；不一致禁止生成航路并提示。

### 4.7 航线与班期 `/admin/network`

**商业航线 `/routes`**

- 列表：dep/arr、距离、block time、最低机型、启用状态、默认航路。
- 新建/编辑：dep/arr 唯一；距离可自动算；block time 可覆盖。
- 批量导入 CSV；错误行可下载。

**班期模板 `/schedules`**

- 列表：航班号、航线、起飞本地时刻、星期、有效期、机型、过站。
- 新建/编辑：航班号唯一（公司内）；时间用机场本地时区；支持复制一周。
- CSV 导入：字段校验、重复航班号、无效机场、时间格式；导入报告。

**航班实例 `/flights`**

- 按日期范围查看；手动「生成未来 N 天」；批量取消/重生成。
- 显示状态、可用飞机、是否被班表占用。
- 修改计划时刻需二次确认，影响已抽中的班表时禁止或提示。

### 4.8 运行监控 `/admin/ops`

**在飞/待复核 `/flights`**

- 筛选：状态、验证结果、日期、飞行员、飞机。
- 详情：轨迹地图、落地指标、配载、结算、校验备注。
- 操作：跳转 `/review` 复核、强制结束、释放飞机。
- 所有操作写审计；强制操作需填原因。

**异常结算复核 `/review`**

- 列出 `settlement.status = HELD` 的航班：异常类型、轨迹、落地指标、配载、预估金额、策略建议。
- 操作：`ACCEPT`（factor=1）/ `WEIGHTED`（可手动改 factor 0–1）/ `REJECT`（factor=0）；必须填原因。
- 处理完写 `settlement`、`ledger_entry`、`audit_log`，并通知飞行员。
- DISPATCHER 可复核；策略本身只有 ADMIN 能改。

**飞机锁定 `/locks`**

- 列表：飞机、谁锁的、类型（班表/自由飞/在飞）、到期时间、心跳。
- 强制释放：二次确认 + 原因；释放后航班标记 `ABANDONED`。

### 4.9 用户 `/admin/users`

- 列表：用户名、显示名、角色、状态、最后登录。
- 新建：用户名、初始密码、角色、邮箱（可选）。
- 编辑：显示名、角色、禁用/启用、重置密码。
- 邀请码：生成/作废、有效期、使用次数。
- 不能删除自己；不能把最后一个 ADMIN 降级。

### 4.10 审计 `/admin/audit`

- 筛选：时间、操作人、动作、实体、结果。
- 列表：时间、操作人、动作、对象、IP、request_id。
- 详情：before/after JSON diff、原因、User-Agent。
- 导出 CSV；保留 90 天（可配置）。
- 审计只读，不提供删除。

### 4.11 系统 `/admin/system`（只读）

- 服务版本、API 版本、客户端最低版本。
- 数据库连接/迁移版本、备份状态。
- navdata AIRAC、route engine 状态、`network.pkl` 校验和。
- 任务队列：最近生成/导入任务。
- 健康检查：DB、route engine、存储。

### 4.12 异常与结算策略 `/admin/policies/settlement`

- 作用范围 `scope_mode`：`COMPANY_ONLY`（默认，仅公司）/ `ALLOW_OVERRIDES`（允许覆盖）。
- 公司默认：`default_action`、`reject_cost_mode`（`FULL` / `DIRECT_ONLY` / `NONE`）、`review_advance_ratio`（0–0.5）、`review_sla_hours`、`min_payout_factor`。
- 异常规则表：数据缺口、时间加速、暂停、瞬移、油量跳变、轨迹距离、轨迹缺失；每行可配启用、动作、阈值、扣减/固定扣减、最高扣减；最低 factor 为全局。
- 覆盖（仅 `ALLOW_OVERRIDES` 显示）：机型 / 单机 / 飞行员三个 Tab；支持「复制公司默认」后局部修改、删除；列表显示目标、修改人、时间。
- 覆盖优先级：飞行员 > 单机 > 机型 > 公司；飞行员覆盖可以放宽机型限制，需管理员自行控制。
- 生效预览：选飞行员 + 飞机，显示合并后的有效策略，并标注每条规则来自公司/机型/单机/飞行员。
- 预览：选择异常组合（如缺口 12min + 3x），显示 factor、收入、成本、利润；同时模拟预付款与成本模式。
- 发布：与经济参数同一套 `version` / audit / rollback；只影响后续航班，已开始航班用快照。
- 运行事件（备降/坠机/落错机场）不在此页，走固定规则。
- 权限：ADMIN 改策略与覆盖；DISPATCHER 只读；PILOT 不可见。

## 5. 参数编辑流程

```
加载当前已发布配置（version=N）
  → 管理员编辑表单（草稿仅浏览器本地，不写服务端）
  → 前端即时校验 + 服务端 Pydantic 校验
  → 预览：跑 100 班合成航班，展示利润/载客率分布
  → 发布：
      1. 再次校验
      2. 检查 version 仍为 N（乐观锁）
      3. 创建 company_config_version（N+1）+ 写 company_setting_history 全量快照 + 更新 company_setting
      4. 写 audit_log（before/after、原因、IP、request_id）
      5. 返回新版本号
  → 下一班航班开始时读取新版本并写入 economy_snapshot（含 settlement_policy）
```

- 已开始的航班继续用旧快照；不回溯已结算航班。
- 并发编辑：第二个发布者收到 `409 CONFIG_VERSION_CONFLICT`，页面展示差异，要求合并/刷新。
- 回滚：选择历史版本 → 生成新版本（内容等于旧版），不删除历史。
- 异常策略页的预览是「异常组合 → factor/收入/成本/利润」，不是 100 班分布；发布/版本/审计流程相同。
- 所有参数修改必须能在审计里还原「谁、何时、改前、改后、为什么」。

## 6. 权限矩阵

## 7. 表单与数据校验

- 所有数值字段：类型、范围、单位、步长；后端 Pydantic 再校验一次。
- 跨字段规则示例：
  - 商务票价 ≥ 经济票价；头等 ≥ 商务。
  - 载客率上限 0.8–1.0；商务比例 0–0.3（默认按机场等级 3%–10%）。
  - 燃油/起降/机组等成本 ≥ 0。
  - 机场需求权重 > 0；时段/星期系数 0.1–3.0。
  - 备降收入系数 0.2–0.8；取消成本系数 0–0.5。
  - 时间加速扣减比例 0–1，且档位递增。
  - `reject_cost_mode` 只能是 `FULL/DIRECT_ONLY/NONE`；`review_advance_ratio` 0–0.5；`scope_mode` 只能是 `COMPANY_ONLY/ALLOW_OVERRIDES`。
- 文本字段：长度、字符集；React 默认转义，禁止 `dangerouslySetInnerHTML`；服务端同样做输出编码。
- 文件上传：CSV/JSON/SQLite，大小限制（默认 512MB，需容纳约 268MB 的 navdata SQLite），MIME 与扩展名双重校验，解析失败给行号。
- 保存前显示「影响预览」：例如燃油价从 1.05→1.10，预计单班成本 +$260。
- 破坏性操作（重置经济、强制释放、删除班期）需输入公司名或勾选确认。

## 8. 安全

| 项 | 措施 |
|---|---|
| 传输 | 公网强制 HTTPS + HSTS；本地单机 `127.0.0.1` 可例外；反向代理终止 TLS |
| 会话 | 随机 256-bit session id；DB 只存哈希；`HttpOnly/Secure/SameSite=Lax`；空闲 30min、绝对 12h |
| CSRF | 每会话同步 token；所有 POST/PUT/DELETE 校验；失败返回 403 |
| 登录 | Argon2id；失败限流；5 次锁定 5 分钟；不区分错误原因 |
| 权限 | 服务端逐路由 `require_role`；公司隔离；禁止 IDOR |
| 注入 | ORM 参数化；React 自动转义；CSP 限制脚本来源；禁止内联脚本 |
| 上传 | 类型/大小/内容校验；解析在受限进程；不执行上传文件 |
| 审计 | 登录、登出、配置变更、危险操作、失败尝试 |
| 部署 | `/admin` 可配 IP 白名单/VPN；管理端与玩家 API 可分开域名 |
| 敏感信息 | 页面不显示密码哈希、token、数据库连接串；日志脱敏 |

- 管理端与玩家 API 共用账号体系，但**会话机制不同**：浏览器用 Cookie，桌面端用 Bearer。
- 前后端不同站点时，Cookie 需 `SameSite=None; Secure` 并配置 CORS `allow_credentials`；优先同域反代，避免跨站 Cookie。
- 管理员可选 2FA（P2）；MVP 先做密码 + 限流 + 审计。

## 9. 非功能要求

| 类别 | 要求 |
|---|---|
| 性能 | 200 架飞机 / 5000 航班列表分页 ≤ 1s；概览 ≤ 2s；表单保存 ≤ 1s |
| 前端体积 | 首屏 JS ≤ 500KB gzip（Ant Design 按需引入）；按路由分包；表格虚拟滚动；图表懒加载 |
| 加载状态 | API 慢/失败时有 skeleton/错误重试，不出现白屏 |
| 浏览器 | Chrome/Edge 最近两个大版本；1280px 以上；支持高 DPI |
| 响应式 | 表格横向滚动；手机仅保证可登录/看概览（不承诺完整编辑） |
| 可用性 | 所有字段有标签、单位、帮助；错误就地提示；未保存离开有确认 |
| 国际化 | 中文默认；文案走 i18n；单位切换（kg/lb、NM/km） |
| 可访问性 | 键盘可操作；表单 label 关联；对比度达标 |
| 审计 | 所有写操作可追溯；保留 90 天；支持导出 |

| W-A05 | 两个管理员同时编辑并发布 | 后发布者收到版本冲突与差异，不覆盖前者 |

## 11. 明确不做（MVP）

- 不做玩家端 Web 抽班/飞行（仍用桌面客户端）。
- 不做公开注册、公司主页、排行榜。
- 不做拖拽式排班/甘特图（P1 评估）。
- 不做跨公司超级管理员。
- 不做服务端渲染（SSR）/模板引擎（Jinja2/HTMX）。
- 不做管理端实时 WebSocket 大屏（轮询足够）。
- 不做移动端完整编辑（只保证可查看）。

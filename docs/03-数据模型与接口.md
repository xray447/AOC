# 03 数据模型与接口

> 版本 v0.1 · 状态：建议方案（待评审）
>
> 约定：主键统一 UUID（`id`）；时间统一 `timestamptz`（UTC）；金额 `numeric(14,2)`；重量 `numeric(10,1)` kg；距离 `numeric(8,1)` NM；坐标 `numeric(9,6)`；所有表带 `created_at`，可变的带 `updated_at`。

## 1. 实体关系

```
company 1──* aircraft_type?（全局模板）
company 1──* aircraft ──1 aircraft_type
company 1──* route 1──* schedule_template 1──* flight_instance
flight_instance 1──* roster_leg *──1 roster *──1 aircraft
roster 1──* roster_leg 1──0..1 flight_record
flight_record 1──* track_chunk
flight_record 1──* flight_event
flight_record 1──1 load_sheet
flight_record 1──1 settlement 1──* ledger_entry
aircraft 1──* aircraft_lock
user 1──* roster / flight_record / ledger?（飞行员维度看 audit）
```

个人模式只使用：`flown_leg`、`flight_record`、`track_chunk`、`flight_event`、`load_sheet`（可空）、`app_setting`。联机模式（M3）使用其余表。

> 里程碑归属：M2 单机运营模式在本机 SQLite 中增加机队/航线/班期/班表/结算/账本/规则版本等表，但**不使用** `app_user`、`company`、`web_session`、邀请码/角色相关表；`company_id` 在 M2 省略（或固定指向本机档案），M3 联机时再启用多租户。本文的 `timestamptz`/`numeric` 精度约定对 M2 改为 SQLite 的 `TEXT(ISO8601)`/`INTEGER(分)`；`/api/v1` 与 `/admin/*` 接口属 M3，M2 由 `aoc-core` 本地接口提供同等能力。
>
> 实施状态（M1，2026-10-20）：`packages/aoc_core/aoc_core/db.py` 已建表 `schema_meta`、`app_setting`、`flown_leg`、`volanta_flight`、`volanta_sync`、`flight_record`、`track_chunk`、`flight_event`（含 `idx_flown_leg_arr/pair`、`idx_flight_created/status`、`idx_event_flight` 与老库补列迁移）。`load_sheet`、`settlement`、`ledger_entry`、`outbox` 与 2.1/2.2/2.4/2.7 的全部表尚未创建，属 M2/M3；轨迹按段落在 `tracks/{flight_id}/{seq}-{mode}.bin.gz`，DB 存元数据与 sha256。

## 2. 表结构

### 2.1 身份与公司

| 表 | 关键字段 | 说明 |
|---|---|---|
| `app_user` | `id, username(uniq), email, password_hash, display_name, role, company_id, status, last_login_at` | `role`: `ADMIN/DISPATCHER/PILOT`；`status`: `ACTIVE/DISABLED` |
| `company` | `id, name, icao_code, callsign_prefix, base_airport_icao, currency, balance, settings_json` | M3 起使用；M2 用本机档案（`profile` 单条记录）替代 |
| `refresh_token` | `id, user_id, token_hash, expires_at, revoked_at` | 只存哈希；桌面客户端用 |
| `web_session` | `id, user_id, session_hash, csrf_token, ip, user_agent, created_at, last_seen_at, expires_at, revoked_at` | 浏览器管理端用；只存 session 哈希 |
| `audit_log` | `id, company_id, actor_user_id, action, entity_type, entity_id, before_json, after_json, reason, ip, user_agent, request_id, created_at` | 只追加 |
| `notification` | `id, company_id, user_id, level, title, body, read_at` | 站内通知 |

### 2.2 机队

| 表 | 关键字段 | 说明 |
|---|---|---|
| `aircraft_type` | `id, icao, variant, name, manufacturer, role, cabin_config_json, pax_capacity, cargo_capacity_kg, mtow_kg, mzfw_kg, mlw_kg, oew_kg, fuel_capacity_kg, cruise_speed_kt, cruise_fl, fuel_burn_kg_h, min_runway_m, range_nm, engine_count, engine_type, wake_category, demand_profile, allow_scheduled, allow_charter, charter_rate_per_hour, fare_multiplier, is_custom` | 全局模板；唯一 `(icao, variant)`；`role`: `AIRLINER/BIZJET/VIP/CARGO/COMBI`；`demand_profile`: `MASS/BIZJET/CARGO/NONE`；公司可复制为自定义 |
| `aircraft` | `id, company_id, type_id, registration(uniq), tail_number, livery, base_airport_icao, current_airport_icao, status, fuel_kg, total_hours, total_cycles, condition_pct, acquisition_type, purchase_price, lease_per_hour, depreciation_per_hour, acquired_at, version` | `status`: `ACTIVE/HELD/IN_FLIGHT/MAINTENANCE/RETIRED`；`version` 乐观锁 |
| `aircraft_lock` | `id, company_id, aircraft_id, user_id, roster_id, flight_record_id, lock_type, status, acquired_at, expires_at, heartbeat_at` | `lock_type`: `ROSTER/FREE/IN_FLIGHT`；`status`: `HELD/IN_FLIGHT/RELEASED/EXPIRED`；部分唯一索引保证一架飞机只有一个 `HELD` 或 `IN_FLIGHT` |

`cabin_config_json` 示例（A340-300 BIZJET）：

```json
{"first": 12, "business": 24, "premium_economy": 0, "economy": 0}
```

- `pax_capacity` = 各舱座位数之和（示例为 36）；不再用「A340 默认 300 座」覆盖公务机构型。
- 该机型：`role=BIZJET`、`demand_profile=BIZJET`、`allow_scheduled=false`、`allow_charter=true`、`charter_rate_per_hour` 按公司配置。
- 普通 A340-300 用 `variant=STANDARD`，公务机用 `variant=BIZJET`；两者 `icao` 都是 A343，但唯一键是 `(icao, variant)`。

### 2.5 飞行记录

| 表 | 关键字段 | 说明 |
|---|---|---|
| `flight_record` | 见下方字段组 | 个人/公司共用；`company_id` 为空即个人 |
| `track_chunk` | `id, flight_record_id, seq, mode, start_t_offset_ms, end_t_offset_ms, sample_interval_ms, encoding, point_count, payload_path, sha256, uploaded_at` | 唯一 `(flight_record_id, seq)`；`mode`: `STRAIGHT/TURN/CLIMB_DESCENT/APPROACH/TAXI/EVENT`；`encoding`: `BIN_V1/JSONL_GZIP`；payload 为 gzip |
| `flight_event` | `id, flight_record_id, t_offset_ms, type, payload_json` | `takeoff/landing/pause/crash/gear/flaps/...` |
| `load_sheet` | `id, flight_record_id, flight_instance_id, aircraft_id, seed, pax_total, pax_economy, pax_premium_economy, pax_business, pax_first, cargo_kg, mail_kg, zfw_kg, tow_kg, fuel_kg` | 航班开始时固化；按机型 `cabin_config` 填充 |
| `settlement` | `id, flight_record_id(uniq), company_id, config_version, revenue_gross, revenue_total, cost_total, profit, payout_factor, advance_amount, policy_action, policy_snapshot_json, policy_breakdown_json, status, review_status, reviewed_by, reviewed_at, review_note, computed_at` | `status`: `PENDING/HELD/SETTLED/VOID`；`review_status`: `NONE/PENDING/APPROVED/REJECTED` |
| `ledger_entry` | `id, company_id, flight_record_id, entry_type, amount, balance_after, description, created_at` | 只追加；`amount` 正为收入、负为支出 |

> 每个 `track_chunk` 即一个段：模式变化、关键事件或每 60s 强制开新段；`mode` 为 `STRAIGHT/TURN/CLIMB_DESCENT/APPROACH/TAXI/EVENT`。

> `settlement.policy_action`: `ACCEPT/REJECT/WEIGHTED/REVIEW`；`payout_factor` 0–1；`advance_amount` 是 HELD 时已预付金额（不重复计入 `revenue_total`）；`policy_breakdown_json` 记录每条异常的动作、扣减、最终系数；`policy_snapshot_json` 保存结算时的策略快照。

`flight_record` 字段组：

| 组 | 字段 |
|---|---|
| 标识 | `id, company_id, user_id, aircraft_id, flight_instance_id, roster_leg_id, mode, callsign, airac` |
| 机场/时间 | `dep_icao, arr_icao, scheduled_dep_utc, scheduled_arr_utc, block_off_utc, takeoff_utc, landing_utc, block_on_utc, block_minutes` |
| 航路 | `route_string, route_source, coverage, altitude_valid, mission_type` |
| 距离/油量 | `distance_nm, fuel_start_kg, fuel_end_kg, fuel_used_kg` |
| 过载 | `max_g_flight, max_g_landing, touchdown_g` |
| 落地 | `touchdown_vs_fpm, touchdown_lat, touchdown_lon, runway_ident, threshold_distance_m, centerline_offset_m, bounce_count, landing_distance_m, landing_rating` |
| 轨迹 | `track_profile_json, track_points, track_bytes, track_fidelity_m, track_sha256, data_gap_seconds` |
| 状态 | `status, validation_status, validation_notes_json, anomaly_flags_json` |

`mode`: `PERSONAL/ROSTER/FREE`；`status`: `RECORDING/COMPLETED/DIVERTED/ABORTED/CRASHED/ABANDONED`；`validation_status`: `PENDING/VALID/SUSPECT/INVALID`。

`track_profile_json` 示例：

```json
{
  "profile": "adaptive_v2",
  "base_hz": 1,
  "encoding": "BIN_V1",
  "max_gap_s": 45,
  "straight_interval_s": 20,
  "turn_interval_s": 2,
  "turn_threshold_deg_s": 4,
  "turn_exit_deg_s": 1.5,
  "climb_descent_interval_s": 5,
  "taxi_interval_s": 10,
  "approach_hz": 1,
  "approach_final_5nm_hz": 2,
  "target_size_kb": 500,
  "fidelity_m": 30
}
```

> 体积预算：2h ≤500KB、3h ≤750KB；超预算时只对 `STRAIGHT/TAXI` 段加强抽稀（20m→50m→100m），仍超则记录 warning，不动 `TURN/APPROACH/EVENT`。`BIN_V1` 约 20–24 字节/点（gzip 前），2h 即使固定 1Hz 也约 170–200KB。

### 2.7 公司配置

| 表 | 关键字段 | 说明 |
|---|---|---|
| `company_config_version` | `id, company_id, version, status, created_by, created_at, published_at, note` | 每次发布一条；`version` 公司内递增；`status`: `PUBLISHED/SUPERSEDED` |
| `company_setting` | `company_id, key, value_json, version, updated_by, updated_at` | 当前已发布参数；主键 `(company_id, key)`；`version` 指向当前配置版本 |
| `company_setting_history` | `id, company_id, version, key, value_json, created_by, created_at` | 每次发布写全量快照；用于对比/回滚；唯一 `(company_id, version, key)` |
| `economy_snapshot` | `id, company_id, flight_record_id, config_version, params_json, policy_sources_json, created_at` | 航班开始时固化；`params_json` 含经济参数 + 合并后的 `settlement_policy`；`policy_sources_json` 记录每条规则来自公司/机型/单机/飞行员；结算只读快照 |

`settlement_policy`（`company_setting` 的一个 key）示例：

```json
{
  "scope_mode": "ALLOW_OVERRIDES",
  "default_action": "REVIEW",
  "reject_cost_mode": "FULL",
  "review_advance_ratio": 0.0,
  "review_sla_hours": 24,
  "min_payout_factor": 0.40,
  "rules": {
    "DATA_GAP": {"enabled": true, "action": "WEIGHTED", "penalty_per_10min": 0.05, "max_penalty": 0.30},
    "SIM_RATE": {"enabled": true, "action": "WEIGHTED", "tiers": [{"gt": 2, "penalty": 0.20}, {"gt": 4, "penalty": 0.50}, {"gt": 8, "action": "REJECT"}]},
    "PAUSE": {"enabled": true, "action": "WEIGHTED", "ratio_gt": 0.20, "penalty": 0.10},
    "TELEPORT": {"enabled": true, "action": "REJECT"},
    "FUEL_JUMP": {"enabled": true, "action": "REVIEW"},
    "TRACK_DISTANCE": {"enabled": true, "action": "REVIEW"},
    "MISSING_TRACK": {"enabled": true, "action": "REVIEW"}
  },
  "overrides": [
    {"scope_type": "AIRCRAFT_TYPE", "scope_id": "A320", "policy": {"rules": {"DATA_GAP": {"action": "REJECT"}}}},
    {"scope_type": "PILOT", "scope_id": "uuid", "policy": {"review_advance_ratio": 0.3}}
  ]
}
```

- `default_action` 用于未列异常；已列异常按 `rules` 覆盖。
- `reject_cost_mode`: `FULL`（全部成本）/ `DIRECT_ONLY`（燃油、起降、地面、空管）/ `NONE`（不扣，结算 `VOID`）。
- `review_advance_ratio`: 0–0.5，默认 0；`HELD` 时按预估利润预付，最终多退少补。
- `scope_mode`: `COMPANY_ONLY`（默认，忽略 overrides）/ `ALLOW_OVERRIDES`；仅公司级设置，不能出现在 overrides；覆盖顺序：机型 → 单机 → 飞行员，越具体优先级越高。示例为 `ALLOW_OVERRIDES`。
- `overrides` 为局部策略（深合并），只写要改的字段；`scope_type`: `AIRCRAFT_TYPE/AIRCRAFT/PILOT`；`scope_id` 分别用机型 id/ICAO、飞机 id、用户 id。
- 与经济参数同一版本机制：修改写 `company_config_version` + `company_setting_history` + `audit_log`。
- 航班开始时把**合并后的有效策略**随 `economy_snapshot` 固化；结算只读快照，后续改策略不影响已结算/已开始航班。

生效预览：

```json
POST /api/v1/admin/settings/settlement-policy/resolve
{
  "pilot_id": "uuid",
  "aircraft_id": "uuid"
}
```

```json
{
  "effective_policy": { "...": "合并后的完整策略" },
  "sources": {
    "DATA_GAP": "PILOT",
    "TELEPORT": "COMPANY",
    "review_advance_ratio": "AIRCRAFT"
  }
}
```

## 3. 状态机

### 3.1 航班实例 `flight_instance.status`

```
SCHEDULED ──assign──► ASSIGNED ──start──► STARTED ──airborne──► AIRBORNE
    │                    │                   │                    │
    │                    │                   │                    ▼
    │                    │                   │                 LANDED
    │                    │                   │                    │
    │                    │                   │                    ▼
    │                    │                   │                SETTLED
    │                    │                   └──abort──► ABORTED
    │                    └──cancel──► CANCELLED
    └──cancel──► CANCELLED
```

- `DIVERTED`：落地机场 ≠ 计划到达；进入 `LANDED` 后由结算标记，不单独做状态，避免状态爆炸。
- 结算 `HELD` 时航班实例保持 `LANDED`；复核为 `SETTLED` 后推进到 `SETTLED`；`VOID` 时保持 `LANDED` 并标记结算无效。
- 航班实例只由服务端状态机推进；客户端不能直接改。

### 3.2 班表 `roster.status`

```
LOCKED ──start first leg──► IN_PROGRESS ──last leg done──► COMPLETED
  │                              │
  ├──redraw──► CANCELLED         └──cancel──► CANCELLED
  └──timeout（首段未开始）──► EXPIRED
```

- `IN_PROGRESS` 不因超时转 `EXPIRED`；只能 `COMPLETED` 或 `CANCELLED`。
- `cancel` 可由飞行员本人、ADMIN、DISPATCHER 发起；首段后取消时剩余航段 `CANCELLED`。

### 3.3 飞机 `aircraft.status`

```
ACTIVE ──hold──► HELD ──start flight──► IN_FLIGHT ──land──► ACTIVE
  │                │                         │
  │                └──release/expire──► ACTIVE
  ├──maintenance──► MAINTENANCE ──done──► ACTIVE
  └──retire──► RETIRED
```

- `HELD` 与 `IN_FLIGHT` 都占用飞机；同一时刻只允许一条 `aircraft_lock.status IN ('HELD','IN_FLIGHT')`。
- 坠机：`IN_FLIGHT → MAINTENANCE`，按 04 文档处理。

### 3.4 飞行校验 `flight_record.validation_status`

```
PENDING ──ok──► VALID
   │
   ├──warn──► SUSPECT ──review──► VALID / INVALID
   └──fail──► INVALID
```

### 3.5 结算 `settlement.status`

```
PENDING ──compute──► SETTLED
   ├──review──► HELD ──approve──► SETTLED
   └──void────► VOID

review_status: NONE ──► PENDING ──► APPROVED / REJECTED
```

- `HELD`：等待人工复核，不写账本；复核后转 `SETTLED` 或 `VOID`。
- `review_status` 与 `status` 分开：`HELD` 时 `review_status=PENDING`；管理员处理后更新。

## 4. REST API

### 4.1 通用约定

- Base：`/api/v1`；本地模式：`/local`（仅监听 `127.0.0.1`）。
- 认证：桌面客户端用 `Authorization: Bearer <access_token>`；管理端 SPA 用 HttpOnly session cookie + CSRF（见 4.9/4.10）；本地模式用启动时生成的本地 token。
- 时间：请求/响应均为 ISO 8601 UTC，例如 `2026-10-19T12:30:00Z`。
- 分页：`?limit=50&cursor=...` → `{ "items": [...], "next_cursor": "..." }`。
- 错误：

```json
{
  "code": "AIRCRAFT_NOT_AT_DEPARTURE",
  "message": "飞机当前位于 RJTT，不能从 ZBAA 起飞",
  "details": {"aircraft_id": "...", "current": "RJTT", "required": "ZBAA"},
  "request_id": "..."
}
```

- 幂等：写接口支持 `Idempotency-Key`；遥测与结算必须支持。
- 乐观锁：更新配置/飞机带 `If-Match: <version>`；冲突返回 `409 VERSION_CONFLICT`。

### 4.2 认证与用户

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/auth/register` | 可开关 | 默认关闭；账号由 ADMIN 创建或邀请码加入 |
| POST | `/auth/login` | 公开 | 返回 access + refresh |
| POST | `/auth/refresh` | 公开 | 刷新 |

```json
{
  "dep": "LROP",

```

`RouteResult` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `OK / REQUIRES_SIMBRIEF / NO_ROUTE / NO_AIRPORT / NAVDATA_MISSING` |
| `route_source` | string | `AIP / GRAPH / NONE` |
| `coverage` | string | `AIP / HIGH_ALT_AIRWAY / NO_HIGH_ALT / OCEANIC / NO_DATA` |
| `altitude_valid` | bool | 航路是否覆盖请求巡航高度 |
| `requires_simbrief` | bool | 是否建议转 SimBrief；不影响 `simbrief_url` 是否存在 |
| `simbrief_url` | string | `dep/arr` 有效即始终返回；有 `route` 则带，无 `route` 则留空让 SimBrief 自算 |
| `coverage_gaps` | array | 缺口起止里程/中心坐标；可为空 |
| `warnings` | array | 面向用户的提示 |
| `route` / `tokens` / `tokens_full` | string/array | 航路串；失败时为空 |
| `distance_nm` / `cruise_fl` | number | 里程与巡航高度 |
| `airac` / `aip_version` / `coverage_version` | string/null | 导航周期、AIP 数据版本、覆盖索引版本 |
| `sid_options` / `star_options` | array | 程序候选 |
| `valid` | bool | 仅表示图合法；高度看 `altitude_valid` |

`REQUIRES_SIMBRIEF` 响应示例：

```json
{
  "dep": "LROP",
  "arr": "LFPG",
  "status": "REQUIRES_SIMBRIEF",
  "route_source": "NONE",
  "coverage": "NO_HIGH_ALT",
  "altitude_valid": false,
  "requires_simbrief": true,
  "simbrief_url": "https://dispatch.simbrief.com/options/custom?orig=LROP&dest=LFPG&type=A320&fl=350",
  "airac": "2609",
  "coverage_version": "2609.1",
  "aip_version": null,
  "route": null,
  "tokens": [],
  "distance_nm": null,
  "cruise_fl": 350,
  "sid_options": [],
  "star_options": [],
  "valid": false,
  "warnings": [
    "直飞走廊中段约 420 NM 无高空航路数据（罗马尼亚/法国部分 FIR），请使用 SimBrief 生成航路"
  ],
  "coverage_gaps": [
    {"start_nm": 380, "end_nm": 800, "center_lat": 47.2, "center_lon": 19.1}
  ]
}
```

- `status=REQUIRES_SIMBRIEF` / `NAVDATA_MISSING` 是业务结果，HTTP 仍返回 `200`；参数错误才用 `422`。
- `coverage` 覆盖检查细节见 02 文档 §9.3；`route_source=AIP` 时即使覆盖不足也优先 AIP，但会给 warning。
- `POST /routes/coverage` 请求 `{dep, arr, cruise_fl}`，只返回 `{coverage, requires_simbrief, coverage_gaps, warnings}`，不返回航路。
- **SimBrief 链接无条件生成**：选定机场后即可调用 `GET /routes/simbrief`，不必等 `/routes/generate`；`RouteResult.simbrief_url` 也始终存在（只要 `dep/arr` 有效）。`route` 查询参数需 URL 编码；不传则 SimBrief 自算。
- **navdata 缺失**：`status=NAVDATA_MISSING`、`route=null`、`requires_simbrief=true`；`GET /routes/simbrief` 不依赖 navdata，仍可用。
- `format=simbrief` 返回预填 URL；`pln` 返回 XML 文件流。

- 错误体与 4.1 约定一致：`{code, message, request_id}`；参数越界统一 `422 PARAM_OUT_OF_RANGE`。

## 5. 同步协议（HTTP 轮询）

### 5.1 拉取变化

```http
GET /api/v1/sync?since=<cursor>&channels=company:uuid,flight:uuid
Authorization: Bearer <access_token>
```

响应：

```json
{
  "cursor": "eyJ2IjoxLCJzZXEiOjEwMjR9",
  "server_time": "2026-10-20T02:15:00Z",
  "events": [
    {
      "seq": 1024,
      "type": "flight.updated",
      "ts": "2026-10-20T02:15:00Z",
      "data": {"flight_id": "uuid", "status": "AIRBORNE"}
    }
  ],
  "has_more": false,
  "snapshot_required": false,
  "reset_required": false
}
```

- 首次调用省略 `since`（或传 `latest`）：返回当前 `cursor`，`events` 为空，`snapshot_required=true`；客户端先拉 REST 快照。
- 之后用上一轮的 `cursor` 续拉；服务端只返回该游标之后的事件。
- `has_more=true`：立即用新 `cursor` 继续拉，直到 `false`。
- `reset_required=true`：游标过期/服务端重建，客户端丢弃本地增量，重新拉快照。
- 轮询间隔：飞行中 5s；空闲 15–30s；失败指数退避（5→10→30→60s）。
- **不建立 WebSocket 长连接**；无 ping/pong。

### 5.2 事件信封

```json
{
  "seq": 1024,
  "type": "flight.updated",
  "ts": "2026-10-20T02:15:00Z",
  "data": { }
}
```

- `seq` 公司内单调递增；客户端按 `seq` 去重，发现跳号先拉快照再继续。
- `cursor` 是不透明字符串，客户端原样保存，不解析。
- 权限：`channels` 里的 `company:*` 需属于该公司；`flight:*` 需是该航班执行人或管理员；越权返回 403。

### 5.3 事件

| 事件 | 触发 | data |
|---|---|---|
| `flight.updated` | 航班状态变化 | `flight_id, status, actual_dep_utc, actual_arr_utc` |
| `aircraft.position` | 在飞位置（10s 节流） | `aircraft_id, lat, lon, alt_ft, gs_kt, ts` |
| `roster.updated` | 班表状态/重抽/到期 | `roster_id, status, expires_at` |
| `flight.completed` | 结算完成 | `flight_id, settlement_id, profit` |
| `settlement.updated` | 结算/复核状态变化 | `flight_id, status, policy_action, payout_factor` |
| `company.balance` | 余额变化 | `balance, currency` |
| `notification` | 站内通知 | `id, level, title, body` |

> 遥测批次确认不在同步事件里：`POST /flights/{id}/telemetry` 的响应直接返回 `{acked_seq}`。

## 6. 遥测协议

### 6.1 批量上报

`POST /flights/{id}/telemetry`，`Content-Type: application/json`（可 gzip），头 `Idempotency-Key: <flight_id>:<seq>`。

```json
{
  "flight_id": "uuid",
  "seq": 42,
  "session_token": "short-lived-token",
  "sim": "msfs2024",
  "sim_version": "1.39.9.0",
  "client_version": "0.1.0",
  "points": [
    {
      "t": 125.5,
      "lat": 35.55312,
      "lon": 139.78123,
      "alt_ft": 12000.0,
      "agl_ft": 11850.0,
      "ias_kt": 250.0,
      "tas_kt": 268.0,
      "gs_kt": 270.0,
      "vs_fpm": 1200.0,
      "pitch": 3.2,
      "bank": 0.1,
      "hdg_true": 180.0,
      "on_ground": false,
      "gear_down": false,
      "flaps": 0,
      "fuel_kg": 5120.0,
      "g": 1.02,
      "sim_rate": 1.0,
      "paused": false
    }
  ],
  "segments": [
    {"start": 0, "end": 12, "mode": "STRAIGHT"},
    {"start": 13, "end": 40, "mode": "TURN"},
    {"start": 41, "end": 58, "mode": "APPROACH"}
  ],
  "events": [
    {"t": 120.0, "type": "takeoff", "data": {"runway": "34L"}}
  ]
}
```

- `t`：相对飞行开始的秒数，单调不减；服务端按 `seq` 去重。自适应采样下 `t` 间隔可变（直行 20s、转弯 2s、进近 1s，最后 5NM 0.5s）。
- `segments`：可选；`start/end` 是 `points` 的下标区间，`mode` 见 `track_chunk.mode`。缺省时服务端按航向/升降率推断。
- 建议按段或每 30–60s 一批；最大 300 点。
- 服务端返回 `{"acked_seq": 42, "received": 60}`。
- 服务端校验：seq 连续、t 单调、坐标合法、速度包线、sim_rate、油量跳变；异常写 `validation_notes_json`。

### 6.2 结束上报

`POST /flights/{id}/finish`：

```json
{
  "session_token": "...",
  "block_off_utc": "2026-10-20T02:05:00Z",
  "takeoff_utc": "2026-10-20T02:18:00Z",
  "landing_utc": "2026-10-20T04:22:00Z",
  "block_on_utc": "2026-10-20T04:31:00Z",
  "dep_icao": "ZBAA",
  "arr_icao": "ZSSS",
  "fuel_start_kg": 8200.0,
  "fuel_end_kg": 3100.0,
  "distance_nm": 618.4,
  "max_g_flight": 1.62,
  "max_g_landing": 1.48,
  "touchdown_g": 1.41,
  "touchdown_vs_fpm": -142.0,
  "touchdown_lat": 31.19790,
  "touchdown_lon": 121.33610,
  "runway_ident": "18L",
  "threshold_distance_m": 320.0,
  "centerline_offset_m": 4.5,
```

- 服务端用已收轨迹复核摘要；不一致以服务端计算为准，并标记 `SUSPECT`。

## 9. 版本与兼容

- API 版本：`/api/v1`；破坏性变更升 `/api/v2`。
- 客户端启动时 `GET /meta` 获取 `min_client_version`、`api_version`、`navdata_airac`、`route_engine_version`。
- 数据库迁移：Alembic；服务端启动前执行；迁移脚本必须可回滚或有备份。
- 遥测协议：`v` 字段；服务端至少兼容当前大版本。
- navdata：航班记录保存 `airac`；回放/复核用当时版本，不因升级而改变历史解释。

# 02 系统架构

> 版本 v0.1 · 状态：建议方案（待评审）

## 1. 设计原则

1. **领域层与界面/框架解耦**：航线、班表、经济、遥测校验都是纯 Python，可 headless 测试。
2. **个人模式零服务端**：不登录、不联网也能飞、能记录、能生成航路。
3. **公司模式服务端是权威**：飞机位置、锁定、配载、结算以服务端为准；客户端可离线但不可作弊。
4. **遥测与业务分离**：SimLink 只负责「采集 + 缓冲 + 上传」，不参与经济与班表判断。
5. **单一导航数据源**：所有机场/跑道/航路点/程序来自同一份 AIRAC 数据库，避免两套数据打架。
6. **先单机、再联机**：公司模式先做「本地服务端 + 单客户端」，同一套 API 再加多人。
7. **渲染在客户端、服务端只提供数据**：桌面端（Tauri + React）与 Web 管理端（React SPA）各自渲染；服务端只提供 JSON 数据与校验，不返回 HTML、不做模板/SSR。

## 2. 运行形态与拓扑

### 2.1 个人模式（单机）

```
┌──────────────── aoc-client (Tauri 2 + React) ────────────────┐
│  个人模式页面：推荐 / 航路 / 日志 / 轨迹回放 / 统计 / 设置     │
└───────────┬──────────────────────────────────┬───────────────┘
            │ 本地 HTTP (127.0.0.1)             │ 本地 HTTP
┌───────────▼──────────────────┐   ┌───────────▼──────────────────┐
│ aoc-core (Python sidecar)    │   │ aoc-simlink (C#/.NET 8)      │
│ 推荐 / 航路 / 经济 / Volanta │   │ SimConnect → 采样 / 事件      │
│ navdata / SQLite             │   │ 本地队列 / 上传               │
└───────────┬──────────────────┘   └───────────┬──────────────────┘
            │                                  │
┌───────────▼──────────────────┐   ┌───────────▼──────────────────┐
│ SQLite (aoc.db) + tracks     │   │ MSFS 2020 / 2024             │
└──────────────────────────────┘   └──────────────────────────────┘
```

- Tauri 外壳负责启动并守护两个 sidecar：`aoc-core.exe`（Python）与 `aoc-simlink.exe`（C#）；随机端口 + token 写入 `%LOCALAPPDATA%/AOC/runtime.json`。
- React UI 只通过本地 HTTP 访问 `aoc-core` / `aoc-simlink`，不直接读 SQLite、不直接 P/Invoke SimConnect。
- `aoc-core` 与 `aoc-simlink` 都只监听 `127.0.0.1`，不对外暴露端口。
- 航路引擎在 `aoc-core` 内：`network.pkl` + navdata；个人模式不需要起独立服务。

### 2.2 公司模式（客户端 / 服务端）

```
┌──────────────── aoc-client (Tauri + React) ────────────────┐   ┌──── admin-web (React SPA) ────┐
│ 公司页面：机队/航班/抽班/配载/结算 + 本地缓存/outbox        │   │ 公司/经济/机队/航点/班期       │
│ ┌ aoc-core (Python) ─────────┐  ┌ aoc-simlink (C#) ──────┐ │   └───────────────┬────────────────┘
│ │ 推荐/航路/Volanta/navdata  │  │ SimConnect → 采样/上传  │ │                   │ HTTPS JSON
│ └─────────────┬──────────────┘  └───────────┬────────────┘ │                   │
└───────────────┼─────────────────────────────┼──────────────┘                   │
                │ HTTPS                       │ HTTPS                            │
                └──────────────┬──────────────┘                                  │
                               ▼                                                 ▼
                ┌──────────────────────────────────────────────────────────────────┐
                │ aoc-server (FastAPI) /api/v1 JSON（含 /admin/*）                  │
                │ 认证/公司/机队/航线/班表/配载/结算/遥测/管理                       │
                └───────────┬──────────────────────────────┬───────────────────────┘
                            │                              │
                  ┌─────────▼──────┐              ┌────────▼─────────────┐
                  │ PostgreSQL 16  │              │ 文件/对象存储          │
                  │ 业务数据        │              │ 轨迹块 / 备份          │
                  └─────────┬──────┘              └──────────────────────┘
                            │
                  ┌─────────▼────────┐
                  │ aoc-route worker │
                  │ network.pkl      │
                  └──────────────────┘
```

- 服务端可单机 Docker Compose 部署，也可只跑在本机（单人公司模式）。
- 客户端是 Tauri + React 外壳，内部拉起 Python `aoc-core` 与 C# `aoc-simlink`；UI 只走本地 HTTP，服务端仍是业务权威。
- 客户端本地仍有 SQLite 缓存（航班、班表、待上传轨迹、设置），断网可继续飞，恢复后补传。
- 客户端定时 `GET /sync` 拉取变化，写操作走 REST POST；MVP **不建立 WebSocket 长连接**。
- 管理端是独立 SPA：静态资源由 Nginx/CDN 托管，数据走 `/api/v1/admin/*`；FastAPI 不返回 HTML/模板。
- 开发时 Vite dev server 代理 `/api` 到 FastAPI；同域部署无需 CORS，分开域名时配置 CORS 白名单。

## 3. 技术选型

| 层 | 选择 | 理由 | 备选 |
|---|---|---|---|
| 客户端 GUI | **Tauri 2 + React 19 + TypeScript + Vite + Ant Design 5** | UI/地图/表格能力强；壳小；Python sidecar 会增加几十 MB | Flet（仅原型/参考） |
| 本地桥 | **HTTP/JSON，`127.0.0.1` 随机端口 + token** | UI 与 Python/C# 解耦；易调试；无长连接 | stdio / gRPC |
| 领域层 | **Python 3.12 + pydantic**（`aoc-core` sidecar） | 复用 `aoc_core`/`aoc_route`/Volanta/navdata；可单测 | TypeScript/Rust 重写 |
| 服务端 | **FastAPI + SQLAlchemy 2.0 + Alembic** | 异步、OpenAPI 自动文档、生态成熟 | Litestar / Django |
| 网页管理端 | **React 19 + TypeScript + Vite + Ant Design 5**（CSR SPA） | 表格/表单密集；与 API 解耦；静态部署简单 | Vue 3 + Element Plus；Svelte |
| 数据库 | 个人 SQLite；公司 **PostgreSQL 16** | SQLite 零运维；PG 支持并发、JSONB、事务 | MySQL |
| 同步 | **HTTP 轮询 `GET /sync` + 定时 POST** | 无长连接、易排障、断线恢复简单 | WebSocket（P2 实时大屏再评估） |
| 任务 | **APScheduler**（生成航班、过期未开始班表释放） | 单进程够用；避免过早引入 Celery | RQ / Celery |
| 航路 | `aoc-route` 封装 `Pre-train` 的 `network.pkl` + `graph_route` | 20ms/对、图合法、无需 torch | SimBrief API |
| 导航数据 | Little Navmap / Navigraph SQLite（只读） | 机场/跑道/航路点/程序齐全，AIRAC 可版本化 | 其他 navdata 格式（需转换） |
| 遥测 | **C#/.NET 8 + 官方 SimConnect SDK** | 最稳的 SimConnect 接入；独立进程崩溃不影响 UI | Python ctypes sidecar |
| 地图 | **MapLibre GL JS / Leaflet / Canvas** | 1 万点轨迹、缩放、图层控制成熟 | Flet map |
| 打包 | **Tauri bundle（MSI/NSIS）+ Python sidecar（PyInstaller）+ C# self-contained** | 一套安装器拉起三进程；WebView2 可用 | 独立安装器 / 分开发布 |

> 注意：`network.pkl` 约 **57 MB**，navdata SQLite 约 **268 MB**，`model.pt` 约 **15 MB**。安装包不随附 navdata；首次运行让用户指定/导入自备的 Little Navmap/Navigraph 数据库，避免许可与体积问题。

## 5. 个人模式关键链路

### 5.1 启动

1. Tauri 启动 `aoc-core` 与 `aoc-simlink` 子进程；读取 `runtime.json`（端口、token）。
2. `aoc-core` 读取设置与本地 DB，执行迁移；检查 navdata 版本，缺失则引导用户选择/导入自备数据库。
3. React UI 通过本地 API 读取状态；轮询 `aoc-simlink` 状态/采样。
4. 若开启 Volanta 自动同步且超过 24h，`aoc-core` 后台尝试同步；失败只提示不阻塞。

### 5.2 推荐 → 航路 → 飞行 → 记录

```
用户输入时间/基地/机型
  → aoc_core.recommend.candidates()   # navdata + 本地日志 + Volanta
  → 用户选机场
  → aoc_route.generate(dep, arr)      # graph_route + SID/STAR + 巡航高度
  → 用户导出 SimBrief / .pln
  → 用户在模拟器飞行
  → SimLink 检测起飞 → 开始记录
  → 检测落地 → 生成 flight_record + track + landing_metrics
  → 客户端展示落地评估与日志
```

### 5.3 自动开始/结束规则

- 开始：`on_ground=false` 且 `AGL > 50ft` 持续 5s，且地速 > 40kt；或用户手动开始。
- 结束：`on_ground=true` 且地速 < 5kt 持续 30s，且发动机停车/驻车刹车；或用户手动结束。
- 若 SimLink 在飞行中退出，重启后从最后一条轨迹继续，标记缺口。

## 6. 公司模式关键链路

### 6.1 抽班表

```
Client POST /rosters/draw {
  aircraft_type?, base?, window_hours?, max_legs?,
  max_block_minutes?, min_turnaround_min?, max_turnaround_min?
}
  → Server 读取可用飞机（ACTIVE、未锁、位置匹配）
  → 读取未来窗口内的航班实例
  → 拼链：硬约束（位置/连续/机型/状态）+ 用户软约束（航段数/总飞行时间/过站/窗口）
  → 评分：多样性、利用率、收益、随机
  → 返回 1-3 个候选（不落库）
Client POST /rosters {candidate_token}  → 创建 roster + 锁飞机（DB 事务 + 唯一约束）
  → 返回 roster 详情
```

- 候选不落库，避免垃圾数据；确认时重新校验飞机仍可用（乐观锁）。
- 锁飞机用 `aircraft_lock` 表 + `(aircraft_id, status='ACTIVE')` 条件更新，冲突返回 409。

### 6.2 自由飞行

```
Client GET /flights/free/aircraft?dep=ZBAA&type=A320
Client POST /flights/free {aircraft_id, flight_instance_id?|dep,arr,dep_time}
  → 校验飞机位置=dep、未被锁、机型匹配、航程够
  → 创建短期锁（30min，心跳续期）
  → 返回 flight_session（配载在 start 时生成，seed = HMAC-SHA256(server_secret, flight_record_id)，见 04 §3.1）
```

### 6.3 飞行与结算

```
POST /flights/{id}/start          → 固化配载、锁转 IN_FLIGHT、返回 session_token
POST /flights/{id}/telemetry      → 批量点 + 事件，幂等 (flight_id, seq)
POST /flights/{id}/finish         → 上传摘要、落地指标、油量、block time
  → 服务端校验 → VALID/SUSPECT/INVALID
  → 计算收入/成本 → 写 ledger（事务）
  → 更新飞机位置/小时/循环/状态
  → 写同步事件 flight.completed + company.balance（客户端下次 GET /sync 获取）
```

### 6.4 网页管理端

```
浏览器加载 admin-web 静态资源（Nginx/CDN）
  → React Router 进入 /admin/login
  → POST /api/v1/admin/auth/login {username, password}
      → 校验 → 设置 HttpOnly session cookie + 返回 CSRF token
  → SPA 进入 /admin/economy
      → GET /api/v1/admin/economy + /api/v1/admin/settings/schema
      → 客户端渲染分组表单（单位/默认值/范围/公式说明）
  → POST /api/v1/admin/settings/economy/preview
      → EconomySimulator.run(当前表单, 100) → 返回 JSON 分布
  → POST /api/v1/admin/settings/economy/publish（X-CSRF-Token, version）
      → Pydantic + 跨字段校验
      → 乐观锁 version（冲突 409）
      → 创建 company_config_version + 写 history + 更新 company_setting + audit_log
      → 下一班读取新版本并写入 economy_snapshot（含 settlement_policy）
```

- 服务端只返回 JSON；`/admin/*` 是 SPA 的 history 路由，由 Nginx `try_files` 回退到 `index.html`，不由 FastAPI 处理。
- Web 与 API 共用 `EconomyService` / `FleetService` / `RouteService`，不重复业务规则。
- 页面只传表单字段；`company_id` 从会话取，禁止前端指定。
- 参数修改不直接写库；草稿仅浏览器本地，发布走 service 的事务 + 审计。
- 预览只读，不写业务表；失败不影响线上配置。
- 异常/结算策略走同一套草稿 → 预览 → 发布 → 审计；复核在 `/admin/ops/review`，复核后写 `settlement` + `ledger`。
- 危险操作（重置经济、强制释放、修改当前位置）要求原因 + 二次确认。

## 7. SimLink 遥测设计

### 7.1 为什么独立进程

- SimConnect 连接与模拟器生命周期绑定，客户端崩溃不应带走遥测。
- **C#/.NET 8 + 官方 SimConnect SDK**：比 Python ctypes 更稳，避免 Python 与原生 DLL 的 ABI/打包问题。
- SimLink 不依赖 Python；`aoc-core` 只通过本地 HTTP 读取它的采样/事件，职责分离。
- MVP 只支持 MSFS；SimLink 适配层保持可替换，但不承诺 X-Plane/其他模拟器。
- 可单独以「无 GUI」方式运行，便于排障与自动化测试。

### 7.2 进程接口

- 可执行文件：`aoc-simlink.exe`（.NET 8 self-contained，不要求用户预装 .NET）。
- 启动参数：`--port 0 --token <random>`；实际端口与 token 写入 `%LOCALAPPDATA%/AOC/runtime.json`。
- 本地 HTTP（仅 `127.0.0.1`）：
  - `GET /status`：模拟器版本、连接状态、当前航班；
  - `GET /samples?since=<seq>`：内部 1Hz 采样点（落盘自适应），客户端按需轮询；
  - `GET /events?since=<seq>`：起飞、落地、暂停、崩溃、sim rate 变化；
  - `POST /command`：`start_recording` / `stop_recording` / `set_rate`。
- 鉴权：`X-SimLink-Token` 本地 token（文件权限限制当前用户）；不监听 `0.0.0.0`。
- 公司模式：SimLink 自己按 30–60s 批量 `POST` 遥测到 `aoc-server`；个人模式：写本地队列，`aoc-core` 读取并落 SQLite。客户端只做展示/控制，不转发遥测。

### 7.3 SimConnect 变量（最小集）

| 类别 | SimVar | 用途 |
|---|---|---|
| 位置 | `PLANE LATITUDE`, `PLANE LONGITUDE`, `PLANE ALTITUDE`, `PLANE ALT ABOVE GROUND` | 轨迹、AGL |
| 姿态 | `PLANE PITCH DEGREES`, `PLANE BANK DEGREES`, `PLANE HEADING DEGREES TRUE` | 姿态、跑道对齐 |
| 速度 | `AIRSPEED INDICATED`, `AIRSPEED TRUE`, `GROUND VELOCITY`, `VERTICAL SPEED` | 包线校验 |
| 状态 | `SIM ON GROUND`, `GEAR HANDLE POSITION`, `FLAPS HANDLE INDEX`, `BRAKE PARKING POSITION` | 阶段识别 |
| 动力 | `GENERAL ENG N1:1`, `GENERAL ENG RPM:1`, `FUEL TOTAL QUANTITY WEIGHT` | 油量、异常 |
| 重量 | `TOTAL WEIGHT`, `EMPTY WEIGHT` | 配载校验 |
| 环境 | `AMBIENT WIND VELOCITY`, `AMBIENT WIND DIRECTION`, `AMBIENT TEMPERATURE` | 记录 |
| 过载 | `G FORCE` | 最大 G |
| 接地 | `PLANE TOUCHDOWN NORMAL VELOCITY`, `PLANE TOUCHDOWN LATITUDE`, `PLANE TOUCHDOWN LONGITUDE` | 落地指标（若可用） |
| 时间 | `SIMULATION RATE`, `ABSOLUTE TIME` | 反作弊、时间轴 |

> `PLANE TOUCHDOWN *` 在部分机模/版本上可能不可用；实现时必须同时保留「on-ground 首帧」兜底路径。

### 7.4 采样、缓冲、上传

**采样与保存分离**：

- 内部采样：`SIMCONNECT_PERIOD_SECOND`，1Hz；进近/着陆可提到 2Hz。用于状态机、事件、异常检测。
- 落盘不是每个采样点都写：按飞行阶段/转弯/升降率自适应保存，转弯密、直行疏。

| 模式 | 触发（初始值） | 保存间隔 |
|---|---|---|
| `STRAIGHT` | 航向稳定、`abs(VS) < 500fpm`、巡航 | 20s，最大 45s |
| `TURN` | 航向变化率 > 4°/s | 2s |
| `CLIMB_DESCENT` | `abs(VS) > 1000fpm` | 5s |
| `APPROACH` | 距到达机场 15NM 或 AGL < 3000ft | 1Hz；最后 5NM 2Hz |
| `TAXI` | on ground、GS < 40kt | 10s |
| `EVENT` | 起飞/落地/起落架/襟翼/暂停/sim rate/崩溃 | 事件前后各 2s 强制保存 |

- 滞回：进入 `TURN` 阈值 4°/s，退出阈值 <1.5°/s 且持续 4s，避免在阈值附近抖动。
- 强制保存：航向变化 > 3°、高度变化 > 300ft、距离 > 2NM、VS 变化 > 800fpm、模式变化。
- 最大间隔：任何模式都不超过 45s（可配置），保证轨迹连续。
- 保真度目标：与内存中的 1Hz 采样对比（不落盘），回放最大偏差 ≤ 30m；进近/转弯段不抽稀。
- 编码：默认 `BIN_V1`（delta 时间 + 定标整数 + gzip，约 20–24 字节/点）；调试可切 `JSONL_GZIP`。
- 体积预算：2 小时 ≤500KB、3 小时 ≤750KB；超预算时只对 `STRAIGHT/TAXI` 段做更强 Douglas–Peucker（20m→50m→100m），仍超则记录 warning，不动 `TURN/APPROACH/EVENT`。

**分段（segment）**：

- 每个 `track_chunk` 就是一个段；模式变化、关键事件、或每 60s 强制开新段。
- 段元数据：`mode`、`start_t`、`end_t`、`sample_interval_ms`、`encoding`。
- 默认 `BIN_V1`：delta 时间 + 定标整数（lat/lon 1e-7、alt ft、gs 0.1kt、hdg 0.1°、VS fpm、fuel 1kg、G 0.001），约 20–24 字节/点，再 gzip。
- 转弯/进近段保留全精度；展示时可再对直行段做 Douglas–Peucker（20m）。
- 体积预算：2h ≤500KB、3h ≤750KB；超预算只压直行/滑行段，事件/转弯/进近不压。
- 上传时带 `segments`（起止索引 + mode）；没有 `segments` 时服务端可按航向重算。

**缓冲与上传**：

- 本地缓冲：`simlink_queue` SQLite 表，字段 `(flight_id, seq, mode, payload, created_at, uploaded_at)`。
- 上传：每段或每 30–60s 一批；指数退避（1s→2s→4s→…→60s）；成功后标记。
- 幂等：服务端以 `(flight_id, seq)` 唯一约束去重。
- 压缩：批量 JSON → gzip；轨迹落盘用 JSONL + gzip。
- 断线：继续写本地；恢复后按 seq 补传；缺口 > 5min 标记 `data_gap`。

### 7.5 异常检测与处置（服务端）

| 检测 | 规则（初始值） | 默认处置（可配置） |
|---|---|---|
| 瞬移 | 相邻点距离 / 时间 > 900 kt 且持续 2 点 | `REJECT` |
| 时间加速 | `sim_rate > 4` 的点占比 > 5% | `WEIGHTED`：2–4x -20%，4–8x -50%，>8x `REJECT` |
| 长时间暂停 | 暂停时长 / block time > 20% | `WEIGHTED`：-10% |
| 数据缺口 | 相邻点时间差 > 5min | `WEIGHTED`：每 10min -5%，最多 -30% |
| 油量跳变 | 单点油量变化 > 总油量 20% | `REVIEW` |
| 轨迹距离 | 轨迹距离 / 大圆距离 < 0.9 或 > 2.5 | `REVIEW` |
| 起降不符 | 实际起降与航班不一致 | 运行事件：按备降处理 |

个人模式只提示，不阻止。公司模式由 `settlement_policy` 决定 `ACCEPT` / `REJECT` / `WEIGHTED` / `REVIEW`；默认动作、阈值、扣减比例、成本模式、预付款比例、作用范围与覆盖均可在网页管理端修改，详见 [04-班表与经济规则.md](04-班表与经济规则.md) §11。

检测只产出异常事件；结算服务按策略执行，不在检测代码里写死「拒绝/折算」。

## 8. Volanta 接入

- 适配器接口：`VolantaSource.fetch() -> list[FlownLeg]`。
- 实现顺序：
  1. `BrowserTokenSource`：复用 `dispatcher/volanta.py` 的 LevelDB 解析，读取本机 Chromium 系浏览器的 Orbx token；调用 `/api/v1/Flights`；
  2. `CsvSource`：用户导出 CSV；
  3. `ManualSource`：手动补录。
- Token 存储：Windows DPAPI（`CryptProtectData`）或系统凭据管理器；**不写明文、不进日志、不上传**。
- 扩展解析：现有实现只取 `originIcao/destinationIcao`；新项目增加日期、机型、时长、落地率字段，字段名需用真实响应验证，解析失败则跳过该字段。
- 缓存：`volanta_cache` 表；同步成功后更新 `last_sync_at`；失败保留旧数据。
- 合规：Volanta 无公开 API，此接入属于「用户本机会话的尽力而为」；文档与 UI 必须提示可能失效，且不提供绕过登录的能力。

## 9. 航路引擎

### 9.1 组件

```python
# aoc_route/service.py
class RouteService:
    def __init__(self, network_path, navdata_path, aip_providers, coverage_index): ...
    def generate(self, dep, arr, aircraft=None, cruise_fl=None, avoid=(), force_graph=False) -> RouteResult: ...
    def simbrief_url(self, dep, arr, aircraft=None, cruise_fl=None, route=None) -> str: ...
    def coverage(self, dep, arr, cruise_fl) -> CoverageResult: ...
    def procedure_choices(self, airport, kind, anchor) -> list[Procedure]: ...
    def validate(self, tokens, cruise_fl=None) -> tuple[bool, str]: ...
```

| 组件 | 职责 |
|---|---|
| `AipRouteProvider` | 按 `dep/arr/fl` 查官方航路；日本先接 jp-routes（复用 `dispatcher/data.py` 的读取/缓存逻辑），其他区域后续 |
| `CoverageIndex` | 从 navdata 建“高空航路覆盖”索引，按 FL 判断直飞走廊是否有高空航路 |
| `GraphRouteEngine` | 封装 `Pre-train` 的 `network.pkl` + `graph_route`，按 `cruise_fl` 过滤边 |
| `SimBriefFallback` | 只要 `dep/arr` 有效就生成预填 URL；`route` 可选；不自动抓取，避免依赖第三方会话 |

- navdata 缺失时 `RouteService` 进入 degraded 模式：不加载 `network.pkl`，只提供 SimBrief 链接。
- `network.pkl` 启动时加载一次，只读；`RouteService` 线程安全。
- 结果缓存：LRU 512，键 `(dep, arr, airac, cruise_fl, aircraft_category, aip_version, coverage_version)`。
- 图路径 `graph_route()` 约 20ms；模型路径（可选）约 4s，默认关闭。
- 服务端可作为独立 worker 运行，避免 FastAPI 进程被 57MB 图与计算阻塞；MVP 可同进程。

### 9.2 固定优先级

```text
generate(dep, arr, cruise_fl):
  simbrief_url = build_url(dep, arr)        # 先建；route 可后补
  0. navdata 检查
       -> 未提供/不可读：NAVDATA_MISSING + requires_simbrief；直接返回链接
  1. AIP 官方航路
       -> 命中：使用 AIP；附 SID/STAR；校验高度/方向；失败只警告
  2. 直飞走廊覆盖检查
       -> 无高空航路覆盖：REQUIRES_SIMBRIEF；默认不调用 Pre-train
  3. Pre-train 图航路
       -> 按 cruise_fl 过滤边；altitude_valid=true 且绕行比 <= 1.9 才可用
       -> 失败/高度不合法/绕行过大：REQUIRES_SIMBRIEF
  4. 返回 simbrief_url
       -> 有 route 则补上；无 route 则留空让 SimBrief 自算
       -> 与 1–3 独立，任何 status 都返回
```

- **SimBrief 链接无条件生成**：只要 `dep/arr` 有效就返回，不依赖 AIP/覆盖/图结果；`simbrief_url` 不是失败时才有的字段。
- `force_graph=true` 是高级选项：允许用户在明确知道风险时跳过覆盖拦截，但仍标警告；默认关闭。
- AIP 优先是硬规则：即使覆盖检查不通过，AIP 命中仍用 AIP，但必须标 `altitude_valid` 与 warning。
- AIP 可能有多条候选：按 `cruise_fl`/EOBT/机型筛选；MVP 取首条或最短，UI 允许切换。
- `valid=true` 只代表图合法；必须另有 `altitude_valid`，不能把低空航路当高空航路返回。

### 9.3 覆盖检查

- 输入：`dep`、`arr`、`cruise_fl`。
- 沿大圆每 **50 NM** 采样；忽略起降端 **50 NM**，避免终端区误判。
- 每个采样点检查 **100 NM** 内是否存在满足 `min_fl <= cruise_fl <= max_fl` 的高空航路边；`max_fl` 为空视为无上限，`min_fl` 为空视为 0。
- 连续缺口 > **200 NM** 或 > **20%** 航程 → `coverage=NO_HIGH_ALT`、`status=REQUIRES_SIMBRIEF`。
- 短程 <200 NM 可跳过覆盖检查。
- 覆盖索引由 navdata 离线构建，随 AIRAC 版本化；FRA/直接航路区域通常没有任何高空命名航路边，会自然判为缺口。
- 输出 `coverage_gaps[]`：起止里程、中心坐标，供 UI 画缺口和提示。

> 目前 `Pre-train/db.py` 读取了 `minimum_altitude/maximum_altitude`，但 `network._build_edges()` 没有使用；必须扩展 `network.pkl` 保存每条边的 `min_fl/max_fl`，否则图本身仍是“高度盲”。这是接入覆盖检查前的前置改造。

### 9.4 输出结构

```json
{
  "dep": "LROP", "arr": "LFPG",
  "status": "REQUIRES_SIMBRIEF",
  "route_source": "NONE",
  "coverage": "NO_HIGH_ALT",
  "altitude_valid": false,
  "requires_simbrief": true,
  "simbrief_url": "https://dispatch.simbrief.com/options/custom?orig=LROP&dest=LFPG&...",
  "airac": "2609",
  "coverage_version": "2609.1",
  "aip_version": null,
  "route": null,
  "tokens": [],
  "distance_nm": null,
  "cruise_fl": 350,
  "sid_options": [],
  "star_options": [],
  "valid": false,
  "warnings": [
    "直飞走廊中段约 420 NM 无高空航路数据（罗马尼亚/法国部分 FIR），请使用 SimBrief 生成航路"

  "coverage_gaps": [
    {"start_nm": 380, "end_nm": 800, "center_lat": 47.2, "center_lon": 19.1}

```

- `status`: `OK / REQUIRES_SIMBRIEF / NO_ROUTE / NO_AIRPORT / NAVDATA_MISSING`。
- `route_source`: `AIP / GRAPH / NONE`。
- `coverage`: `AIP / HIGH_ALT_AIRWAY / NO_HIGH_ALT / OCEANIC / NO_DATA`。
- `simbrief_url` 只要 `dep/arr` 有效就始终存在；`requires_simbrief=true` 时它仍是同一个字段，只是 UI 要显示醒目警告和 SimBrief 按钮。
- `requires_simbrief=true` 时，UI 必须显示醒目警告和 SimBrief 按钮，不能静默返回航路。

### 9.5 降级策略

| 情况 | 行为 |
|---|---|
| navdata 未提供/不可读 | `NAVDATA_MISSING` + `requires_simbrief=true`；直接给 SimBrief，不生成航路 |
| AIP 命中 | 用 AIP；附 SID/STAR；`route_source=AIP` |
| 无 AIP，覆盖检查通过，图成功 | 用图；`route_source=GRAPH`，`altitude_valid=true` |
| 无 AIP，覆盖检查失败 | `REQUIRES_SIMBRIEF`；不调用 Pre-train（除非 `force_graph`） |
| 覆盖通过，但图无解/高度不合法/绕行 >1.9 | `REQUIRES_SIMBRIEF`；不伪造 DCT 航路 |
| 机场不在图内 | `NO_AIRPORT` + SimBrief |
| NAT/PACOTS 等海洋航路 | `coverage=OCEANIC` + SimBrief/手工 |
| navdata 与 network.pkl 版本不一致 | 启动时校验 AIRAC，不一致则禁用航路生成 |
| 图引擎异常 | `REQUIRES_SIMBRIEF`，不阻塞飞行记录 |

### 9.6 数据版本

- `navdata_meta`：AIRAC、生效日期、来源、校验和、导入时间。
- `network.pkl` 的 AIRAC 必须与 navdata 一致；并带每条边的 `min_fl/max_fl`。
- `coverage_index` 与 AIRAC 同版本；AIP provider 带 `aip_version`。
- 航班记录保存 `airac`、`route_source`、`coverage`、`altitude_valid`，回放/复核时用当时版本解释航路。

### 10.1 个人模式

| 数据 | 位置 | 说明 |
|---|---|---|
| 业务数据 | `%LOCALAPPDATA%/AOC/aoc.db` | SQLite WAL；表见 03 文档 |
| 轨迹 | `.../tracks/{flight_id}/{segment}.bin.gz` | 按段存储（STRAIGHT/TURN/APPROACH/TAXI/EVENT）；默认 BIN_V1，调试可 JSONL |

| 日志 | `.../logs/` | 滚动 7 天 |
| 备份 | `.../backups/` | 每日 zip，保留 7 份 |

### 10.2 公司模式

| 数据 | 位置 | 说明 |
|---|---|---|
| 业务数据 | PostgreSQL | 用户、公司、机队、航班、班表、账本 |
| 轨迹块 | 文件系统 `data/tracks/{flight_id}/{seq}-{mode}.bin.gz` 或 S3/MinIO | 按段存储；默认 BIN_V1；DB 存 mode/起止时间/校验和 |
| 实时状态 | 内存 + DB | 在飞位置可 5s 落库一次，不必每点写 DB |
| 备份 | `pg_dump` + 文件快照 | 每日；保留 14 天 |

### 10.3 一致性

- 结算：`flight_record`、`ledger`、`aircraft`、`company.balance` 在同一事务。
- 异常结算：`HELD` 默认不写 `ledger`（若配置预付款则只写 `ADVANCE_PAYOUT`）；`REJECT` 收入 0、成本按 `reject_cost_mode`；复核后在同一事务写 `settlement` + `ledger` + `audit_log`。
- 锁：`aircraft_lock` 唯一索引 `(aircraft_id) WHERE status IN ('HELD','IN_FLIGHT')`（PG 部分索引）。
- 上传幂等：`track_chunk(flight_id, seq)` 唯一。
- 客户端 outbox：`(id, endpoint, payload, idempotency_key, retry_count, next_retry_at)`。

## 11. 同步与离线

### 11.1 轮询同步

- 客户端定时 `GET /api/v1/sync?since=<cursor>&channels=company:uuid,flight:uuid`，**不建立 WebSocket 长连接**。
- 轮询间隔：飞行中 **5s**；空闲 **15–30s**；连续失败指数退避（5→10→30→60s）。
- 服务端返回 `{cursor, events[], has_more, snapshot_required, reset_required}`；客户端只处理新事件，`cursor` 持久化到本地。
- 首次调用省略 `since` 时 `snapshot_required=true`，客户端先拉 REST 快照。
- `has_more=true` 时立即用新 `cursor` 继续拉，直到 `false`；避免一次事件过多。
- 断线/重启：用最后 `cursor` 续拉；若服务端返回 `reset_required=true`，先拉全量快照，再继续轮询。
- 事件表（与原事件同 payload，只是改为同步返回）：

| 事件 | 载荷 |
|---|---|
| `flight.updated` | flight_id, status, actual times |
| `aircraft.position` | aircraft_id, lat, lon, alt, ts |
| `roster.updated` | roster_id, status, expires_at |
| `flight.completed` | flight_id, settlement summary |
| `settlement.updated` | flight_id, status, policy_action, payout_factor |
| `company.balance` | balance, currency |
| `notification` | level, title, body |

- 权限：`company:*` 需属于该公司；`flight:*` 需是该航班执行人或管理员。
- MVP **不做 WebSocket**；P2 如果要做实时大屏/高密度地图，再单独评估。

### 11.2 定时 POST

- 遥测：SimLink 每 30–60s 一批 `POST /flights/{id}/telemetry`；带 `Idempotency-Key`。
- 在飞位置：SimLink 每 10s 一次轻量 `POST /flights/{id}/position`，只更新最新点，不代替完整遥测。
- 锁心跳：客户端每 60s `POST /flights/{id}/lock/heartbeat`。
- 写操作仍走普通 REST；`GET /sync` 只读，不承担写入。

### 11.3 离线队列

- 所有写操作先落本地 `outbox`，再尝试发送；成功后删除。
- 读操作走本地缓存；缓存过期显示「离线数据」角标。
- 冲突：服务端返回 409 时，客户端拉取最新状态并提示用户；不自动覆盖。
- 锁心跳：自由飞行/班表锁每 60s 续期；客户端离线超过 TTL，服务端释放锁并标记航班 `ABANDONED`。

## 12. 安全、合规与数据许可

| 项 | 措施 |
|---|---|
| 传输 | 公网公司模式强制 HTTPS；本地单机 `127.0.0.1` 可例外；自签证书需显式信任 |
| 本地 sidecar | `aoc-core`/`simlink` 只监听 `127.0.0.1`；随机端口 + 一次性 token；`runtime.json` 仅当前用户可读 |
| 密码 | Argon2id；不少于 10 位；登录失败 5 次锁定 5 分钟 |
| 会话 | Access token 15min + Refresh token 30 天；刷新令牌可撤销 |
| 管理端会话 | Cookie `HttpOnly/Secure/SameSite=Lax`；空闲 30min、绝对 12h；DB 只存 session 哈希 |
| 管理端 CSRF | 每会话同步 token；所有 POST/PUT/DELETE 校验；失败返回 403 |
| 权限 | 每个 API 校验 `company_id` 与角色；禁止跨公司访问；PILOT 禁止 `/api/v1/admin/*`；前端路由守卫仅改善体验 |
| 跨域 | 优先同域反代；分开域名时只允许配置的 Origin + `allow_credentials`，Cookie 用 `SameSite=None; Secure` |
| 前端 | 静态资源版本化 + SRI；CSP 限制脚本来源；不在 localStorage 存 token；锁定依赖版本 |
| 遥测 | 客户端签名（HMAC，密钥由服务端下发，短期有效）；服务端校验 seq/时间/包线 |
| 审计 | 配置修改、强制释放、结算、封禁写 `audit_log`，不可篡改（只追加） |
| Volanta | 非官方接口；仅个人模式；token 本机加密；不提供共享/代理服务 |
| Navigraph | 数据按用户许可使用；不随安装包分发；服务端由管理员自行导入 |
| SimBrief | MVP 只用公开预填 URL；P1 用官方 API + 用户自己的 key |
| 航司品牌 | 默认虚构；允许用户导入真实品牌/涂装，风险由导入者承担；不随包分发 |
| 隐私 | 个人模式默认零上传；公司模式上传前告知；支持导出/删除个人数据 |

- 前置反向代理（Caddy/Nginx）负责 TLS。
- 生产建议同一域名：`/` → `admin-web` 静态文件，`/api` → FastAPI；同域无 CORS。
- 也可分开域名：`admin.example.com` 托管 SPA，`api.example.com` 提供 JSON；需配置 CORS 白名单与 Cookie `SameSite`。
- 服务端不提供 `/admin` 页面，只提供 `/api/v1/admin/*`；`/admin/*` 的刷新由 Nginx `try_files $uri /index.html` 处理。
- 迁移：容器启动前 `alembic upgrade head`。
- 单人公司模式：客户端提供「打开管理端 / 启动本地服务端」入口；服务端用本机 PostgreSQL（Docker Compose 一键起），与联机模式共用同一套 schema 与迁移。

> 简化建议：公司模式 MVP 先只支持 PostgreSQL（Docker 一键起），不做 SQLite 公司库，避免两套 SQL 方言。

## 14. 可观测性与运维

- 客户端：Tauri 外壳日志、Python/C# sidecar 健康状态、崩溃转储、最近上传错误。
- 服务端：请求日志（含 `request_id`）、慢查询、错误率、同步轮询 QPS/延迟、锁数量、待复核航班数。
- 管理端：登录失败、权限拒绝、配置发布/回滚、强制释放、CSV 导入结果；全部带操作人与 IP。
- 健康检查：`/healthz`（进程）、`/readyz`（DB + navdata + route engine）。
- 指标（P1）：Prometheus `/metrics`；Grafana 面板。
- 告警（P1）：结算失败、上传积压、锁泄漏、navdata 版本不一致。

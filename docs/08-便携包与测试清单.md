重建与自检：

```powershell
python -X utf8 tools\make_portable.py --build    # 构建前端 + dotnet publish → out/AOC-portable-0.1.0-win64.zip
python -X utf8 tools\smoke_portable.py           # 解压到临时目录 + 起服务 + demo 飞行冒烟
```

已知限制：便携包是**浏览器 + 本地服务**，不是 Tauri 窗口；窗口内存、WebView2 行为、安装/卸载只看安装包（§4.5）。当前 v0.1.0 仍调用系统 Python、SimLink 为 framework-dependent；改造为自包含（`aoc-core.exe` + `--self-contained` SimLink，D-30）后用户机器不再需要 Python/.NET，具体见 §4.4.1 与 [09](09-M1交付说明.md) §5。`start.bat` 仅保留为排障入口，双击时会显示控制台。

两个踩过的坑（已在 v0.1.0 修正，后续别改回去）：

1. **入口文件名与内容必须纯 ASCII**。最初叫 `启动探针.bat` 且内含中文提示，cmd 按控制台代码页（936）解析 UTF-8 字节，把 `cd /d` 等行拆坏，报出一串 `'in' is not recognized`，并误判 `server.py` 不存在。现为 `start.bat`，提示信息全英文，中文说明只放 `README.txt`。
2. **不要用 `python start.bat` 启动**。`.bat` 是批处理，交给 Python 必然 `SyntaxError`；那种报错与包本身无关。直接双击，或命令行 `.\start.bat`。

## 4. MSVC / 构建工具链（出 MSI 的前置）

### 4.1 为什么必须装

Tauri 在 Windows 上用 **MSVC ABI** 编译 Rust 代码，`rustc` 生成目标文件后需要 `link.exe`（来自 Visual Studio 的 C++ 生成工具）链接成 exe。缺任何一半都会在 `cargo build` 阶段失败，且 **npm 层无法绕过**。M1 打包机已补齐（WebView2 Runtime 155.0.4283.62 已存在，打包时无需再装运行时）：

```
cargo / rustc / rustup  → 已安装（stable-x86_64-pc-windows-msvc）
VS 2022 Build Tools（MSVC v143 + Windows SDK） → 已安装
WebView2 Runtime 155.0.4283.62 → 已存在
```

下面的安装步骤保留给新的打包机参考。

### 4.2 需要装什么

| 组件 | 用途 | 体积 |
|---|---|---|
| Rustup + stable-x86_64-pc-windows-msvc | 编译 Rust（Tauri 外壳） | ~1.2 GB |
| VS 2022 Build Tools → **Desktop development with C++**（MSVC v143 + Windows 10/11 SDK） | 提供 `link.exe`、`cl.exe`、SDK 头文件 | ~3–5 GB |

合计约 4–6 GB 磁盘、15–40 分钟（视网速）。编译器只需在**打包机**上装一次，用户机器不需要。

### 4.3 安装（管理员 PowerShell）

```powershell
winget install --id Rustlang.Rustup -e --accept-package-agreements --accept-source-agreements
winget install --id Microsoft.VisualStudio.2022.BuildTools -e `
  --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended" `
  --accept-package-agreements --accept-source-agreements
```

装完重开终端，确认：

```powershell
cargo -V ; rustc -V
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -property installationPath
```

`cargo -V` 有输出且 vswhere 能打印路径，即具备打包条件。若 `cargo build` 报 `link.exe not found`，在「x64 Native Tools Command Prompt for VS 2022」里执行，或先跑 `vcvars64.bat`。

### 4.4 打 MSI / NSIS

配置已就绪（`apps/client/src-tauri/tauri.conf.json`：`bundle.active=true`、`targets=["nsis","msi"]`、NSIS `installMode=perMachine`、`webviewInstallMode=downloadBootstrapper`、中英双语、图标已生成；`bundle.resources` 只带前端 `dist`、`out/core/aoc-core`（自包含 exe 目录）与 `simlink` publish 目录，不再打 Python 源码）：

```powershell
cd apps\client
npm.cmd run tauri build -- --bundles nsis
npm.cmd run tauri build -- --bundles msi
```

产物（M1 已生成，随后复制到 `out/` 便于分发）：

```
apps\client\src-tauri\target\release\aoc-client.exe
apps\client\src-tauri\target\release\bundle\nsis\AOC_0.1.0_x64-setup.exe   → out\AOC-0.1.0-x64-setup.exe
apps\client\src-tauri\target\release\bundle\msi\AOC_0.1.0_x64_en-US.msi   → out\AOC-0.1.0-x64.msi
```

首次编译 8–15 分钟（约 450 个 crate），之后增量 1–3 分钟；本次实测 NSIS 2.44 MiB、MSI 3.11 MiB。

### 4.4.1 自包含 sidecar（去 Python / .NET 依赖）

目标：用户机器只装 AOC 就能跑，不需要 Python、.NET、Node。

```powershell
# 1) aoc-core.exe（打包机的 Python 3.12 环境；脚本封装了 PyInstaller 参数）
pip install -r requirements.txt pyinstaller
python -X utf8 tools/build_core_exe.py --verify   # 产物 out/core/aoc-core/aoc-core.exe

# 2) SimLink（自包含，不要求 .NET 8）
dotnet publish apps/simlink -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=false -o apps/simlink/bin/Release/net8.0/win-x64

# 3) 便携包（AOC-portable.exe 托盘启动器 + 自包含 core/simlink + 前端）
python -X utf8 tools/make_portable.py --no-core
```

- 入口是 `apps/aoc-core/entry.py`（先固定 `AOC_ROOT`，再调 `main.main()`）；资源根目录在冻结后指向 `_MEIPASS`（onedir 即 `_internal/`），`data/` 随包发布。
- `--noconsole` 去掉 `aoc-core` 的控制台窗口；冻结版没有 `sys.stdout/stderr`，`main.py` 会先把它们接到 `logs/stdout.log`、`logs/stderr.log`，否则 `uvicorn` 的 formatter 会 `Unable to configure formatter 'default'` 直接退出。
- `numpy/scipy` 必须打进包（航路建图依赖），这是体积主要来源；`tzdata` 不能漏（Windows 时区）。实测 onedir 合计约 **134 MB**（含 numpy/scipy/tzdata）；打包机上 `torch`/`pandas`/`PIL` 等无关大件已用 `--exclude-module` 排除。
- 航路图内核（建图 + Dijkstra 求解）已内置在 `packages/aoc_route/aoc_route/net`（`network/db/geo/config` 四个模块，只依赖 numpy + scipy），随 `--hidden-import aoc_route` / `--collect-submodules aoc_route` 进包；干净 checkout（没有 `Pre-train`）也能构建，不再依赖外部目录。图数据 `network.pkl` 仍不入库：首次启动用用户 navdata 现场建图，失败时图航路降级到 SimBrief，不影响启动。`Pre-train` 只保留训练侧，`AOC_PRETRAIN` 可指向它做算法对照。
- `apps/simlink` 已改为 `<OutputType>WinExe</OutputType>`；日志由父进程（Tauri / `AOC-portable.exe`）重定向到 `%LOCALAPPDATA%\AOC\logs\simlink.log`。
- 先出 `--onedir`（启动快、易排障）；确认稳定后再评估 `--onefile`（每次启动解压，首启慢）。
- 与 `AOC-portable.exe` / Tauri 的资源目录保持一致：两者都指向同一个 `aoc-core.exe`。
- 验证：干净 Windows（无 Python/.NET）上按 T-01、T-06a 跑；`/local/health` 正常、航路建图可用或按预期降级。

| T-06c | WebView2 缺失 | 在未装 WebView2 的镜像上安装 | bootstrapper 自动下载安装成功；断网时应给出明确提示而非白屏 |
| T-06d | 卸载残留 | 卸载后检查 | `Program Files\AOC` 清空；`%LOCALAPPDATA%\AOC`（用户数据）按设计保留并可手动删除 |
| T-06e | 覆盖升级 | 装 0.1.0 后装 0.2.0 | 无需先卸载；用户数据与配置保留 |
| T-06f | 非管理员账户 | 受限用户安装 | 装到用户目录，不写 `Program Files` |
| T-05 | sidecar 互拉 | 安装版启动后杀 `aoc-core` | 前端 3s 内显示断连；后端自动重启；`seq` 续传无缺口；连开 10 次无端口冲突 |

### 4.6 不装 MSVC 的退路

- **只用便携包**：新的打包机未装工具链时先发 ZIP（M1 已可用），代价是没有安装体验与 WebView2 兜底。
- **Electron 打包**：不需要编译器，但偏离 D-03/D-25 的 Tauri 决策，只适合紧急演示。
- 不建议 `x86_64-pc-windows-gnu`（MinGW）：官方非推荐路径，NSIS 打包与 WebView2 行为更容易出问题。

### 4.7 CI 构建（GitHub Actions）

`.github/workflows/build.yml`，`runs-on: windows-latest`，触发：`push`（main / tag `v*`）、`pull_request`、`workflow_dispatch`（可选 `bundle=nsis|msi|both`、`make_release`）。

| 作业 | 内容 | 产物 |
|---|---|---|
| `test` | Python 3.12 + `pip install -r requirements.txt -r requirements-server.txt ruff`（`tests/test_server.py` 需要 SQLAlchemy 等服务端依赖）→ `ruff check packages apps tests tools --select F,E9` → `pytest`；`npm ci && npm run build`（含 `tsc --noEmit`）；`dotnet build apps/simlink -c Release` | 无（PR 只跑这一项） |
| `core` | `pip install ... pyinstaller` → `tools/build_core_exe.py --verify` | `aoc-core-win64` |
| `simlink` | `dotnet publish -c Release -r win-x64 --self-contained true` | `aoc-simlink-win64` |
| `app` | 下载 core/simlink 产物到资源目录 + `dtolnay/rust-toolchain@stable` + cargo 缓存 → `npm run tauri build -- --bundles <list>` | `aoc-installers`（`*-setup.exe`、`*.msi`） |
| `portable` | 下载 core 产物 + 前端构建 → `tools/make_portable.py --no-core` | `aoc-portable-win64` |
| `release` | tag `v*` 或 `make_release=true` 时用 `softprops/action-gh-release` | 草稿 Release |

- 缓存：`setup-python` 的 pip、`setup-node` 的 npm、`Swatinem/rust-cache`（`apps/client/src-tauri`）、`setup-dotnet` 自带的 NuGet 缓存。
- 约束：navdata / `network.pkl` / SimBrief key 不进仓库与产物；`timeout-minutes: 45`；artifact `retention-days: 14`；签名（Authenticode）等有证书再补。

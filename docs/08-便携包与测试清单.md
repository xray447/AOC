## 2. 便携包现状（M1）

| 项 | 值 |
|---|---|
| 文件 | `out/AOC-portable-0.1.0-win64.zip`（929,321 B） |
| 内容 | `app/`（前端 dist）、`packages/`、`apps/aoc-core/`、`data/`、`apps/simlink/`（`dotnet publish -r win-x64`）、`start.bat`、`start.py`、`README.txt` |
| 运行依赖 | Windows 10/11 x64 + PATH 中的 **Python 3.10+**；SimLink 为 framework-dependent，需 **.NET 8**；在线底图需联网（可切离线经纬网） |
| 启动 | 双击 `start.bat` → `start.py` 先拉起 `aoc-simlink.exe`（若存在），再用当前解释器起 `aoc-core` 并打开浏览器到随机端口 |
| 用户数据 | `%LOCALAPPDATA%\AOC`（`aoc.db` / `tracks` / `logs` / `backups`），不写安装目录 |
| 自检结果 | `python tools/smoke_portable.py` → 解压 + 起服务 + demo 飞行 ZBAA→ZSSS（157 pts）通过 |

重建与自检：

```powershell
python -X utf8 tools\make_portable.py --build    # 构建前端 + dotnet publish → out/AOC-portable-0.1.0-win64.zip
python -X utf8 tools\smoke_portable.py           # 解压到临时目录 + 起服务 + demo 飞行冒烟
```

已知限制：便携包是**浏览器 + 本地 Python 服务**，不是 Tauri 窗口；窗口内存、WebView2 行为、安装/卸载只看安装包（§4.5）。安装包不内置 Python 解释器，见 [09](09-M1交付说明.md) §5。

两个踩过的坑（已在 v0.1.0 修正，后续别改回去）：

1. **入口文件名与内容必须纯 ASCII**。最初叫 `启动探针.bat` 且内含中文提示，cmd 按控制台代码页（936）解析 UTF-8 字节，把 `cd /d` 等行拆坏，报出一串 `'in' is not recognized`，并误判 `server.py` 不存在。现为 `start.bat`，提示信息全英文，中文说明只放 `README.txt`。
2. **不要用 `python start.bat` 启动**。`.bat` 是批处理，交给 Python 必然 `SyntaxError`；那种报错与包本身无关。直接双击，或命令行 `.\start.bat`。

### 3.2 现在就能做的（T-01、T-02）

**T-01 跨机冷启动**

1. 把 `out/AOC-portable-0.1.0-win64.zip` 拷到一台**没装过 Node** 的机器，解压到桌面（路径含空格/中文名也测一次）。
2. 双击 `start.bat`。
3. 判据：窗口打印 `SimLink started`（若包内含 exe）与 `AOC core ... listening on http://127.0.0.1:<port>`；浏览器自动打开；3s 内出现首页，`/local/health` 里 `navdata.available` 与 `simlink_connected` 符合预期。
4. 反向用例：把 Python 从 PATH 移除 → `start.bat` 打印 `Python 3.10+ was not found on PATH` 并暂停，而不是闪退。

**T-02 回放压力**

1. 打开一条记录详情，播放速度选 `240×`（可选 1/4/16/60/240×），让 1 万点跑完（约 8s）。
2. 反复拖时间轴 10 次，每次停顿 1s；同时切 2D/3D 地图与高度/地速曲线。
3. 判据：航线连续无断裂、光标不跳变；拖动后 < 100ms 完成重绘、无白屏；无 JS 报错（`tools/ui_smoke.py` 的 `js_errors` 应保持 0）。

### 3.3 需要真实模拟器（T-03、T-04）

M1 的产品链路本身就是探针（`apps/simlink`，默认走 SimConnect，不带 `--demo/--replay` 即为真实采集）：

```powershell
# 终端 1：真实 SimConnect，1Hz 采样，数据落 %LOCALAPPDATA%\AOC
apps\simlink\bin\Release\net8.0\win-x64\aoc-simlink.exe --port 0 --hz 1
# 终端 2：本地 API + 前端（会自动发现 simlink-runtime.json）
python -X utf8 apps\aoc-core\main.py --port 0 --static-dir apps\client\dist --open
```

- 判据：`/local/health` 中 `simlink_connected=true`；连续采集 ≥600s 无断连，`/local/simlink/status` 的采样计数与时长匹配；落地后在「飞行日志」生成完整记录并识别跑道。
- 精度比对：把 `touchdown_vs_fpm`、`max_g_landing/touchdown_g` 与机模仪表 / SimBrief 落地报告对比，VS 差 ≤100 fpm、G 差 ≤0.1。
- 需要逐帧报告时仍可用 M0 探针：`cd spikes\simconnect_probe; dotnet run -- --sim --seconds 600 --hz 1 --airport RJTT`，产物放 `spikes/simconnect_probe/out/sim_<date>/`。

## 4. MSVC / 构建工具链（出 MSI 的前置）

### 4.1 为什么必须装

Tauri 在 Windows 上用 **MSVC ABI** 编译 Rust 代码，`rustc` 生成目标文件后需要 `link.exe`（来自 Visual Studio 的 C++ 生成工具）链接成 exe。缺任何一半都会在 `cargo build` 阶段失败，且 **npm 层无法绕过**。M1 打包机已补齐（WebView2 Runtime 155.0.4283.62 已存在，打包时无需再装运行时）：

```
cargo / rustc / rustup  → 已安装（stable-x86_64-pc-windows-msvc）
VS 2022 Build Tools（MSVC v143 + Windows SDK） → 已安装
WebView2 Runtime 155.0.4283.62 → 已存在
```

下面的安装步骤保留给新的打包机参考。

### 4.2 需要装什么

| 组件 | 用途 | 体积 |
|---|---|---|
| Rustup + stable-x86_64-pc-windows-msvc | 编译 Rust（Tauri 外壳） | ~1.2 GB |
| VS 2022 Build Tools → **Desktop development with C++**（MSVC v143 + Windows 10/11 SDK） | 提供 `link.exe`、`cl.exe`、SDK 头文件 | ~3–5 GB |

合计约 4–6 GB 磁盘、15–40 分钟（视网速）。编译器只需在**打包机**上装一次，用户机器不需要。

### 4.3 安装（管理员 PowerShell）

```powershell
winget install --id Rustlang.Rustup -e --accept-package-agreements --accept-source-agreements
winget install --id Microsoft.VisualStudio.2022.BuildTools -e `
  --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended" `
  --accept-package-agreements --accept-source-agreements
```

装完重开终端，确认：

```powershell
cargo -V ; rustc -V
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -property installationPath
```

`cargo -V` 有输出且 vswhere 能打印路径，即具备打包条件。若 `cargo build` 报 `link.exe not found`，在「x64 Native Tools Command Prompt for VS 2022」里执行，或先跑 `vcvars64.bat`。

### 4.4 打 MSI / NSIS

配置已就绪（`apps/client/src-tauri/tauri.conf.json`：`bundle.active=true`、`targets=["nsis","msi"]`、NSIS `installMode=perMachine`、`webviewInstallMode=downloadBootstrapper`、中英双语、图标已生成；`bundle.resources` 带前端 dist、`packages/`、`data/`、`apps/aoc-core`、`simlink` publish 目录）：

```powershell
cd apps\client
npm.cmd run tauri build -- --bundles nsis
npm.cmd run tauri build -- --bundles msi
```

产物（M1 已生成，随后复制到 `out/` 便于分发）：

```
apps\client\src-tauri\target\release\aoc-client.exe
apps\client\src-tauri\target\release\bundle\nsis\AOC_0.1.0_x64-setup.exe   → out\AOC-0.1.0-x64-setup.exe
apps\client\src-tauri\target\release\bundle\msi\AOC_0.1.0_x64_en-US.msi   → out\AOC-0.1.0-x64.msi
```

首次编译 8–15 分钟（约 450 个 crate），之后增量 1–3 分钟；本次实测 NSIS 2.44 MiB、MSI 3.11 MiB。

### 4.5 打包后新增的必测项

| ID | 测试 | 步骤 | 判据 |
|---|---|---|---|
| T-06a | MSI 安装 | 干净 Win10 虚拟机双击 MSI | 无 UAC 报错；开始菜单有快捷方式；启动 3s 内出图 |

### 4.6 不装 MSVC 的退路

- **只用便携包**：新的打包机未装工具链时先发 ZIP（M1 已可用），代价是没有安装体验与 WebView2 兜底。
- **Electron 打包**：不需要编译器，但偏离 D-03/D-25 的 Tauri 决策，只适合紧急演示。
- 不建议 `x86_64-pc-windows-gnu`（MinGW）：官方非推荐路径，NSIS 打包与 WebView2 行为更容易出问题。

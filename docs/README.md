# AOC 模拟飞行运行中心 · 文档

> 版本 v0.3 · 2026-10-21 · 状态：需求基线（01–06 的细项待评审）+ M1 个人模式已交付（见 [09](09-M1交付说明.md)）+ M2 单机运营模式已交付（见 [10](10-M2交付说明.md)）

## 1. 产品定位

AOC 是面向模拟飞行玩家的桌面软件，提供以下运行形态：

- **个人模式**：单机飞行助理。汇总 Volanta 与模拟器数据，按可用时间推荐没飞过的机场，记录飞行轨迹与落地数据，生成并导出航路。
- **运营模式（单机，M2）**：一个应用内完成机队、航线与航班、抽班表、自由飞行、配载与经济结算；数据落本机 SQLite，不部署服务端。不建账号、公司、角色、邀请码，只有一个本机档案。
- **联机模式（M3）**：多人（也可单人）航司运行。客户端 / 服务端分离，包含机队、航线与航班、抽班表、自由飞行、配载与经济结算；管理员通过**浏览器管理端**修改公司参数。签派（DISPATCHER）与管理员可向**在飞机组**推送 CPDLC 上行报文（公司运行类消息，非真实空管链路）：机组登录 Hoppie 则经 Hoppie 投递，未登录则直接推送到 AOC 客户端通知。

三种形态共用同一套领域模型、遥测链路和航路引擎；个人模式与单机运营模式不依赖服务端，联机模式不依赖 Volanta。

## 3. 关键决策（基线）

状态说明：**建议** = 文档按此设计，评审可改；**待确认** = 需要用户拍板；**已定** = 不再讨论。

| ID | 决策 | 状态 |
|---|---|---|
| D-01 | 仅支持 **MSFS 2020 / 2024**，通过本地 SimLink 代理接 SimConnect；不做 X-Plane | 已定 |
| D-02 | 个人模式纯本地单机；M2 单机运营模式同样纯本地（一个应用，无服务端/无账号/公司/角色/邀请码）；M3 联机模式多人自托管，客户端 / 服务端分离 | 已定 |
| D-03 | 技术栈：Tauri 2 + React 19/TS 桌面客户端 + Python `aoc-core` sidecar + C#/.NET 8 SimLink + SQLite；FastAPI 服务端 + React/TS Web 管理端 + PostgreSQL 自 M3 联机模式起加入 | 已定 |
| D-04 | 导航数据统一使用 Little Navmap / Navigraph SQLite（AIRAC 版本化），由用户自备；航路引擎以 `Pre-train` 图为主干，叠加 AIP 真值层与覆盖检查 | 已定 |
| D-05 | Volanta 是**可选数据源**，不是唯一真相；AOC 自己的飞行日志才是权威记录 | 建议 |
| D-06 | 运营模式的航班来自「航线 + 班期模板 + 每日航班实例」（M2 本地配置，M3 服务端配置），不是凭空随机 | 建议 |
| D-07 | 抽班表以「配对（pairing）」为单位锁定一架飞机；软约束由用户每次抽班设定；首段开始前可重抽（无冷却/费用/次数）；开始后无总任务时限，只能飞完或由本人/ADMIN/DISPATCHER 取消 | 已定 |
| D-08 | 经济结算以校验后的飞行结果为准（M2 本地校验、M3 服务端校验）；M3 离线飞行先入账为「待核验」，核验后补差 | 建议 |
| D-09 | 所有时间以 UTC 存储，客户端按本地时区显示；班期以本地时刻配置 | 建议 |
| D-10 | M2 单机运营模式不需要服务端；M3 起单人也可以起本地服务端；架构不为「必须多人」做假设 | 建议 |
| D-11 | 运营模式默认虚构航司与呼号；允许用户自行导入真实品牌/涂装，风险由导入者承担，不随包分发 | 已定 |
| D-12 | 个人模式默认不上传任何数据；Volanta token 只留在本机 | 已定 |
| D-13 | M3 联机模式提供**浏览器管理端**，管理员可修改公司/经济/机队/航点/航线/班期/用户参数；M2 的管理配置在桌面客户端内完成 | 已定 |
| D-14 | 网页管理端采用 **React 19 + TypeScript + Vite** 的客户端渲染 SPA；服务端只提供 `/api/v1/admin/*` JSON，不返回 HTML、不做模板/SSR | 已定 |
| D-15 | 网页管理端只面向 **ADMIN**（P1 加入 DISPATCHER，M3 起）；PILOT 使用桌面客户端，不提供玩家 Web 端 | 已定 |
| D-16 | 前端静态资源由 Nginx/CDN 托管，API 独立部署；开发用 Vite dev server 代理 `/api` | 建议 |
| D-17 | 运营模式的异常/数据缺口处置可配置：`ACCEPT` / `REJECT` / `WEIGHTED` / `REVIEW`；`reject_cost_mode`（FULL/DIRECT_ONLY/NONE）、`review_advance_ratio`（0–0.5）、`scope_mode`（默认/机型/单机/M3 起飞行员覆盖）均可调 | 已定 |
| D-18 | 轨迹采用自适应稀疏 v2 + `BIN_V1`：直行 20s、转弯 2s、最大间隔 45s；按模式分段；2h ≤500KB、3h ≤750KB；回放偏差目标 ≤30m | 已定 |
| D-19 | 航路优先级：**AIP 官方航路 > 覆盖检查（无高空航路则要求 SimBrief）> Pre-train 图航路**；默认不让 Pre-train 穿越无高空航路区域 | 已定 |
| D-20 | SimBrief 链接与航路生成解耦：选定 `dep/arr` 即生成；有航路带 `route`，无航路留空让 SimBrief 自算 | 已定 |
| D-21 | 客户端/服务端同步用 **HTTP 轮询 `GET /sync` + 定时 POST**；MVP 不建立 WebSocket 长连接 | 已定 |
| D-22 | 机型增加 `role/variant/cabin_config/demand_profile`；`BIZJET`/`VIP` 不套用干线载客模型，公务机走整机包机或无收入任务 | 已定 |
| D-23 | 用户未提供 navdata 时，航路生成返回 `NAVDATA_MISSING`，直接给 SimBrief 链接，不伪造航路 | 已定 |
| D-24 | 商业模式为免费/开源；VATSIM/IVAO 仅 P2 只读，不做客户端 | 已定 |
| D-25 | 客户端采用 Tauri + React；Python `aoc-core` 以本地 HTTP sidecar 提供领域/航路能力；C# SimLink 独占 SimConnect | 已定 |
| D-26 | 新增 **CPDLC 上行报文**：DISPATCHER / ADMIN 可在网页管理端向**在飞机组**发送文本报文（如高度/航路/油量/延误/返航指令），机组在客户端收到并可回执（ACK / 拒绝 / 自由回复）；报文与回执落库并进飞行事件流，用于审计与后续争议判定。投递通道见 D-27 | 建议 |
| D-27 | CPDLC 报文**通道自动降级**：机组填写并在线的 Hoppie（Hoppie ACARS）→ 走 Hoppie 报文，与模拟器内 CDU/ACARS 界面一致；机组未登录 Hoppie → 直接推送到 AOC 客户端通知（应用内消息中心 + 系统通知），点击可回执。同一报文只走一条通道，不双发（Hoppie 投递超时/失败则降级到客户端通知并标注原因）；通道选择与投递结果（已投递/已读/超时）记录在报文上 | 已定 |

## 4. 术语

| 术语 | 含义 |
|---|---|
| 个人模式 | 单机形态，只有本地库，无账号、无服务端 |
| 单机运营模式 | M2 形态：仍是一个应用 + 本地库，增加机队、航班、班表、经济；无服务端、无账号、无公司、无角色、无邀请码 |
| 公司模式 | M3 联机形态：客户端 + 服务端，有机队、航班、班表、经济与账号体系 |
| 航段 Leg | 一次起飞到落地，对应一个航班实例 |
| 航班实例 Flight | 某日某时刻执行的一个航班号，`dep/arr/scheduled_dep` 唯一确定 |
| 配对 Pairing | 连续 1–8 个航段 + 一架飞机的任务包，是抽班表的最小单位；段数/时长/过站由用户抽班时设定 |
| 班表 Roster | 飞行员抽到的配对及其时间窗口、锁定状态 |
| 自由飞行 | 不抽班表，直接选一架空闲飞机 + 一个航班（或自定航线）执行 |
| 配载 Load Sheet | 某班实际承运的旅客 / 货物 / 邮件 / 燃油 / 业载 |
| 结算 Settlement | 航班完成后计算收入、成本、利润并写入账本 |
| SimLink | 本地代理进程，负责 SimConnect 连接、遥测采集与本地缓存 |
| PIREP | 飞行报告，一次飞行的结构化结果 |
| AIRAC | 导航数据周期，28 天一个版本 |
| CPDLC 报文 | 签派 / 管理员发给在飞机组的文本指令，模拟管制数据链上行格式；属公司内部运行通信，不代表真实 ATC 放行 |
| 上行 / 回执 | 签派 → 机组为上行（uplink）；机组 ACK / 拒绝 / 回复为回执（downlink / ACK） |
| Hoppie | Hoppie ACARS 第三方数据链网络，机组以呼号/登录码接入；AOC 仅将其作为报文投递通道，不改变报文语义 |

## 5. 现有资产复用

工作区已有两个可复用项目，新项目不直接改它们，而是抽取为独立包：

| 资产 | 位置 | 复用方式 |
|---|---|---|
| 分层思想（计算 / 视图模型 / 渲染分离） | `japan-flight-dispatcher/dispatcher/` | 作为 `aoc-core` 与 React UI 的分层参考；**不复用 Flet UI** |
| Volanta 读取（浏览器 localStorage token + `/api/v1/Flights` + CSV 兜底） | `dispatcher/volanta.py` | 抽成 `aoc-integrations/volanta` 适配器，扩展字段解析 |
| 机场 / 跑道 / 程序 / 天气采集 | `dispatcher/{procedures,weather,operations,ntrack}.py` | 复用数据模型与降级策略 |
| 机型库 | `dispatcher/aircrafts.json` | 作为机型模板初始数据（212 项） |
| 日本移管点 / 运行规则 | `transfer_points.json`、`operation.json` | 作为公司模式「航路点 / 运行规则」的参考数据 |
| 航路图引擎 | `Pre-train/src/{network,infer,geo}.py` + `artifacts/network.pkl` | 包成 `aoc-route` 服务，`graph_route()` 约 20ms/对 |
| 导航数据库 | `Pre-train/dataset/little_navmap_navigraph.sqlite` | 作为统一 navdata，AIRAC 版本化后只读挂载 |

**注意**：`japan-flight-dispatcher` 的 Volanta 实现依赖浏览器会话，属于非官方接口，存在失效与 ToS 风险；文档将其定位为「尽力而为的可选同步」，并提供 CSV 导入与手动补录作为兜底。

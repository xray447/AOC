## 1. 目标与非目标

### 1.1 目标

1. 让个人玩家在**一个 GUI 应用**里完成：看已飞记录 → 选一个没飞过的机场 → 生成航路 → 飞 → 自动记录 → 回看轨迹与落地品质。
2. 让玩家在**一个应用**里完成运营（M2 单机）：配机队 → 排航线 → 抽班表/自由飞 → 拿配载 → 飞 → 结算 → 看账本；M3 起同样流程可由一群玩家在一个公司里协作完成。
3. 个人模式、单机运营模式与联机模式共享同一套飞行记录、遥测与航路能力，避免两套代码。

### 1.2 非目标

- 不做真实航空公司的运行手册、MEL、性能计算、载重平衡适航级计算。
- 不做 3D 渲染、飞机系统模拟、地景制作。
- 不做空管客户端，不替代 VATSIM / IVAO；VATSIM/IVAO 仅 P2 只读状态，不做客户端。
- 不做移动端。
- 不做面向公众的虚拟航司 Web 门户或玩家 Web 端；公司内部管理端不在此列，见 §6。

## 2. 用户角色

| 角色 | 使用模式 | 能做什么 |
|---|---|---|
| 个人玩家 | 个人模式 | 全部个人功能；无需账号 |
| 单机运营者 | 单机运营模式（M2） | 无需账号；配置机队/航线/班期/经济参数/异常策略，抽班、自由飞、结算、复核 |
| 公司管理员 | 联机模式（M3） | 配置机型/飞机/航点/航线/班期/经济参数；管理用户；查看全公司数据 |
| 签派员（P1） | 联机模式（M3） | 调整航班、给飞行员分配任务、处理异常；不能改经济参数 |

### 2.2 核心用户流程

个人模式：

```
启动 → 数据源状态（Volanta/SimLink/navdata）
     → 输入可用时间、基地、机型
     → 推荐未飞机场（Top 5）
     → 选机场 → 生成航路 → 导出 SimBrief/.pln
     → 模拟器飞行 → SimLink 自动记录
     → 落地 → 轨迹 + 最大 G + 接地点 + 评级
     → 日志/统计/地图更新
```

公司模式：

```
登录 → 公司概览
     → 抽班表（或自由飞行）
     → 确认配对 → 飞机锁定 → 查看配载/收益预估
     → 开始航班 → SimLink 采集 → 批量上传
     → 落地 → 服务端校验 → 结算 → 账本/余额更新
     → 下一段（班表）或释放飞机（自由飞）
```

## 3. 个人模式（Personal）

### P-01 桌面 GUI 与本地档案（MVP，MUST）

- 必须是桌面 GUI，不是命令行；Windows 10/11 x64 优先。
- 首次启动创建本地数据目录：`%LOCALAPPDATA%/AOC/`，含 `aoc.db`、`tracks/`、`logs/`、`cache/`。
- 无需账号、无需联网即可使用全部核心功能。
- 提供「导出档案 / 导入档案」为单个 zip，便于换机与备份。
- 支持深色/浅色主题；中文为默认语言，预留英文。

### P-02 Volanta 同步（MVP，SHOULD）

- 目标：读取用户在 Volanta 的已飞记录，用于「没飞过」判断与统计。
- 数据源优先级：
  1. Volanta 私有 Web API（复用现有 `volanta.py` 的浏览器 token 方案）；
  2. Volanta CSV 导出导入；
  3. 手动补录（机场对 + 日期 + 机型）。
- 解析字段：起降 ICAO、执行日期、机型（若可得）、飞行时长（若可得）、落地率（若可得）。
- 同步策略：手动触发 + 启动时若超过 24h 自动尝试一次；失败静默降级，不阻塞主流程。
- 去重键：`(dep_icao, arr_icao, date, aircraft_type)`；无日期时用 `(dep, arr)` 聚合计次。
- 明确提示：这是非官方接口，可能随时失效；不会上传 token，不会把数据发给第三方。
- **AOC 本地飞行日志是权威**：Volanta 只补历史，不覆盖 AOC 自己记录的航班。

### P-03 按航程时间推荐未飞机场（MVP，MUST）

输入：

- 可用时间（滑块：30min–6h，或自定义）；
- 出发地：当前所在机场 / 常用基地 / 手动选择；
- 机型（可选，影响航程与跑道要求）；
- 偏好：只去没去过的、优先没去过的国家/地区、最大距离、是否要求有地景（可选）。

推荐逻辑：

1. **候选生成**：以出发地为中心，按大圆距离筛出 0.6–1.4 倍目标航程的机场；过滤跑道长度不足、无导航数据、无进场程序的机场。
2. **未飞判定**：默认「从未作为到达机场去过」；可切换「从未起降过」「近 N 年没去过」。
3. **时间估算**：`block_time ≈ 距离 / 机型巡航速度 + 爬升/下降修正 + 滑行 10min`，给出区间而非单点。
4. **评分**：未飞加成、时间匹配度、跑道/程序匹配度、国家/地区多样性、地景存在（可选）、随机扰动。
5. **输出**：Top 5–10，卡片展示 ICAO/IATA、机场名、国家、距离、预计航时、未飞原因、推荐理由；可一键「生成航路」或「在 map 上看」。

验收要点：给定 90 分钟和「从未到达」，返回至少 5 个候选，预计航时落在 75–105 分钟内，且都不是已到达过的机场。

### P-04 模拟器遥测接入（MVP，MUST）

- 通过本地 **SimLink（C#/.NET 8）** 进程连接 MSFS SimConnect；客户端不直接持有 SimConnect 句柄。
- 仅支持 MSFS 2020 与 2024；X-Plane 不做。
- 自动检测飞行阶段：`PREFLIGHT → TAXI → TAKEOFF → CLIMB → CRUISE → DESCENT → APPROACH → LANDING → TAXI_IN → SHUTDOWN`。
- 内部采样默认 1 Hz；进近/着陆段可提到 2 Hz。**采样不等于落盘**：保存按 P-05 的自适应策略，转弯/进近加密，直行稀疏。
- 记录变量（最小集）：
  - 位置：纬度、经度、海拔、AGL；
  - 姿态：俯仰、横滚、真航向、磁航向；
  - 速度：IAS、TAS、GS、垂直速度；
  - 状态：起落架、襟翼、刹车、发动机 N1/RPM、油量、总重；
  - 环境：风向/风速、温度、QNH；
  - 完整性：sim rate、暂停状态、SimConnect 连接状态。
- 断线/暂停：本地缓存继续记录（暂停时记录暂停段），恢复后补传；断线超过 5 分钟标记数据缺口。
- 反异常：检测瞬移（相邻点距离/时间不合理）、时间加速（sim rate > 4）、异常油量跳变，标记 `SUSPECT` 但不在个人模式阻止记录。
- 用户可一键「开始记录 / 结束记录」，也支持自动检测起飞后开始。

### P-05 轨迹记录与回放（MVP，MUST）

- 轨迹按航班、按段存储：`flight_id` + **段（segment）** + 点序列 + 事件序列；每段独立文件/记录，避免单文件过大，支持断点续传。
- **分段规则**：飞行阶段变化、采样模式变化、关键事件、或每 60s 强制切段；每段记录 `mode`（`STRAIGHT/TURN/CLIMB_DESCENT/APPROACH/TAXI/EVENT`）、起止时间、点间隔、编码方式。
- **自适应保存（稀疏 v2）**：
  - 直行巡航：默认 20s 一点，最长不超过 45s；
  - 转弯：航向变化率 > 4°/s 时 2s 一点；退出转弯需低于 1.5°/s 持续 4s（滞回，避免抖动）；
  - 爬升/下降：|VS| > 1000 fpm 时 5s 一点；
  - 进近/着陆：距到达机场 15 NM 或 AGL < 3000 ft 起 1 Hz；最后 5 NM 2 Hz；
  - 滑行：10s 一点；
  - 事件：起飞、落地、起落架、襟翼、暂停、sim rate 变化、崩溃时强制保存前后 2s。
- 强制保存：航向变化 > 3°、高度变化 > 300ft、距离 > 2NM、VS 变化 > 800fpm、模式变化。
- 存储：本地 SQLite 元数据 + `tracks/{flight_id}/{segment}.bin.gz`（默认紧凑二进制 `BIN_V1`，可切 JSONL 调试）。
- 体积目标：**2 小时航班 ≤500KB**，3 小时 ≤750KB；若超预算，只对 `STRAIGHT/TAXI` 段做更强抽稀（20m→50m→100m），仍超则提示，不动 `TURN/APPROACH/EVENT`。
- 展示抽稀：直行段可用 Douglas–Peucker（20 m）；转弯/进近段不抽稀，保留形状。
- 回放：稀疏段线性插值，转弯段用原始点；显示高度/速度曲线，支持 1x–16x。
- 可选：设置里切换「固定 1 Hz」或「固定 2 Hz」；二进制编码下 2 小时固定 1 Hz 约 170–200KB。
- 导出：GPX、CSV、JSON；可导出单航班或全部。
- 地图：React + MapLibre/Leaflet + CARTO 瓦片；显示起降机场、航路点、轨迹、事件标记。

### P-06 落地评估（MVP，MUST）

落地窗口定义为「首次接地前 10 秒到接地后 5 秒」，记录：

| 指标 | 说明 | 来源 |
|---|---|---|
| `max_g_landing` | 窗口内最大 G 值（过载） | SimConnect `G FORCE` 采样 |
| `touchdown_g` | 首次接地瞬间 G 值 | 同上 |
| `touchdown_vs_fpm` | 接地垂直速度 | `PLANE TOUCHDOWN NORMAL VELOCITY` 或 VS 采样 |
| `touchdown_lat/lon` | 首次接地坐标 | `PLANE TOUCHDOWN LATITUDE/LONGITUDE` 或首帧 on-ground |
| `runway_ident` | 识别到的跑道 | 最近跑道 + 航向对齐 |
| `threshold_distance_m` | 距跑道入口距离 | 跑道阈值坐标 + 投影 |
| `centerline_offset_m` | 距跑道中线横向偏移 | 跑道方位 + 投影 |
| `bounce_count` | 接地后再次离地次数 | on-ground 状态翻转 |
| `landing_distance_m` | 接地到完全停下的距离 | 接地后滑跑积分 |
| `max_g_flight` | 全程最大 G 值（可选） | 全程采样 |

- 跑道识别：在 navdata 中找 5 NM 内、航向差 < 30° 的跑道；多个候选取最近。
- 落地评级：`GREAT / GOOD / HARD / SEVERE`，阈值可配置（例如 VS：< -100 / -100~-300 / -300~-600 / < -600 fpm；G：< 1.5 / 1.5–1.8 / 1.8–2.2 / > 2.2）。
- 个人模式只记录不惩罚；公司模式进入结算与飞机损伤模型。

### P-07 航路生成（MVP，SHOULD）

**固定优先级**：

0. **navdata 检查**：用户未提供 Little Navmap/Navigraph 数据，或数据不可读 → `status=NAVDATA_MISSING`、`requires_simbrief=true`，**直接给 SimBrief 链接**；不执行 AIP/覆盖/图。
1. **AIP 官方航路**：按 `dep/arr`（以及时段/机型）查询 AIP 提供商；命中且基本合法 → 直接使用。日本用 jp-routes；其他区域后续接入。
2. **覆盖检查**：沿大圆每 50 NM 采样（忽略起降端 50 NM），检查 100 NM 内是否存在覆盖请求巡航高度的高空航路边。若连续缺口 >200 NM 或 >20% 航程 → `coverage=NO_HIGH_ALT`、`status=REQUIRES_SIMBRIEF`，**明显提示使用 SimBrief**，默认不再调用 Pre-train。
3. **Pre-train 图航路**：仅当 AIP 未命中且覆盖检查通过；按 `cruise_fl` 过滤边；要求 `altitude_valid=true`、绕行比 ≤1.9；否则同样提示 SimBrief。
4. **SimBrief 兜底**：选定机场后**立即**生成预填链接（不依赖航路结果）；有航路则带 `route`，无航路则留空让 SimBrief 自算。

- 输入：`dep`、`arr`、机型、`cruise_fl`、避让航路（可选）、`force_graph`（高级，默认关）。
- 首次运行向导未选择 navdata 时，航路生成直接禁用；用户选好机场后仍可点 SimBrief。
- 输出：
  - 主干航路串（折叠）/逐点航路（`tokens_full`）；
  - 航路总里程、预计航时、建议巡航高度；
  - SID/STAR 候选（程序名 + 跑道 + 里程）；
  - `status`: `OK / REQUIRES_SIMBRIEF / NO_ROUTE / NO_AIRPORT / NAVDATA_MISSING`；
  - `route_source`: `AIP / GRAPH / NONE`；
  - `coverage`: `AIP / HIGH_ALT_AIRWAY / NO_HIGH_ALT / OCEANIC / NO_DATA`；
  - `altitude_valid`、`requires_simbrief`、`simbrief_url`；
  - `warnings[]`、`coverage_gaps[]`（缺口起止里程/中心坐标）。
- AIP 优先：即使覆盖检查不通过，AIP 命中仍用 AIP，但标 `altitude_valid` 与警告。
- **SimBrief 链接无条件生成**：只要 `dep/arr` 有效就返回；是否有 AIP/图航路都不影响链接存在。
- UI：选定机场后即显示「打开 SimBrief」按钮；覆盖不足时顶部红色警告，主按钮改为「打开 SimBrief」，默认不显示 Pre-train 航路卡片。
- 短程 <200 NM 可跳过覆盖检查，避免终端区误判。
- 不允许把低空航路当高空航路返回；`valid=true` 只代表图合法，必须另看 `altitude_valid`。
- 缓存键：`(dep, arr, airac, aircraft_category, cruise_fl, aip_version, coverage_version)`。
- 航路生成是**辅助**，不替代机组判断；界面必须显示数据来源、AIRAC、覆盖状态。

### P-08 导出与 SimBrief（MVP，SHOULD）

- 一键复制航路串。
- **选定机场后立即生成 SimBrief 预填 URL**（复用 `simbrief_params.md` 的参数契约），不依赖是否生成航路；有航路时带 `route`，无航路时让 SimBrief 自算。
- 导出 MSFS `.pln`（XML）；X-Plane `.fms` 不做。
- 导出内容包含：dep/arr、SID/STAR、跑道、巡航高度、航路串、备降（若有）。

### P-09 飞行日志与统计（MVP，MUST）

- 日志列表：日期、航班号/呼号、机型、起降、 block time、距离、最大 G、落地 VS、评级。
- 详情：轨迹回放、航路、落地评估、事件时间线、备注、截图（可选）。
- 统计：总小时、总距离、机场数、国家数、机型分布、月度飞行次数、落地率分布、最大 G 记录。
- 地图：已飞机场/航线的世界地图，可筛选年份与机型。

### P-10 设置（MVP，MUST）

- 数据源：Volanta 开关、SimLink 连接状态、navdata 版本。
- 单位：英尺/米、节/公里每小时、磅/千克。
- 记录：密度模式（自适应/固定 1 Hz/固定 2 Hz）、自动开始、是否记录滑行、最大间隔（默认 45s）、转弯阈值（高级，默认 4°/s）。
- 隐私：是否允许匿名统计（默认关）、导出/清除本地数据。
- 外观：主题、语言、地图瓦片源。

## 4. 公司模式 · 客户端（Company Client）

> 里程碑归属：本节按联机形态（M3）描述。M2 单机运营模式在客户端内提供同类页面（机队/航线/班表/抽班/自由飞/配载/结算/复核），但**没有** C-01 的服务器地址、账号、邀请码、在线人数，也**没有**角色与上传校验；所有判断在 `aoc-core` 本地完成，C-08 的「上传/服务端校验」在 M2 退化为本地校验与落库。

### C-01 登录与公司（M3，MUST）

- 服务器地址 + 账号密码登录；支持「记住我」与刷新 token。
- 首次登录选择/加入公司：邀请码加入，或管理员创建。
- 显示公司名、呼号前缀、基地机场、当前余额、在线人数。
- 离线时进入「只读缓存」：可看已缓存航班与班表，不能抽班/开始新航班。

### C-02 机队（MVP，MUST）

- 列表：注册号、机型、当前位置、状态（可用/锁定/飞行中/维护）、总小时、循环数、剩余寿命（可选）。
- 筛选：基地、机型、状态、位置。
- 详情：机型参数（载客/载货/MTOW/航程/巡航速度/油耗）、当前油量、所属航班/班表、最近飞行记录。
- 只读展示为主；增删改由服务端/管理员完成。

### C-03 航班与航线（MVP，MUST）

- 航线网络列表：`dep – arr`、距离、预计航时、最低机型类别、是否公司航线。
- 航班实例列表：航班号、日期、计划起降（本地/UTC 切换）、机型要求、状态、可用飞机。
- 筛选：出发/到达、日期范围、机型、状态、基地。
- 航班详情：航路（公司航线优先）、SID/STAR 建议、天气（P1）、备降（P1）、配载预览、收益预估。
- 选择航班后：
  - 若走班表：只能选班表内的航段；
  - 若自由飞行：校验飞机当前位置 = 出发机场、机型匹配、时间窗口。
- **关键校验**：飞机必须在出发机场；不满足时给出「调机」建议或禁止。

### C-04 抽班表（MVP，MUST）

- 入口：「抽班表」按钮；用户可自由设定非硬约束参数：
  - 机型、基地（可空）；
  - 窗口：默认 24h，范围 1–168h；
  - 最大航段数：默认 3，范围 1–8；
  - 总飞行时间：默认 480min，范围 30–1440min（仅用于候选筛选，不是运行时限）；
  - 最小过站：默认 45min，范围 15–240min；
  - 最大过站：默认 360min，范围 30–1440min。
- 服务端生成候选配对：从可用飞机 + 航班实例中拼链，满足：
  - **硬约束**：飞机当前位置 = 第一段出发机场；前一班到达 = 后一班出发；机型匹配；飞机 `ACTIVE` 且未被锁定；
  - **软约束**：按用户设置的航段数、总飞行时间、最小/最大过站、窗口筛选。
  - `allow_scheduled=false` 的机型（如公务机）不进入普通抽班；走包机/自由飞。
- 返回 1–3 个候选，展示：飞机、航段列表、总时间、总距离、预计收入、难度/多样性评分；同时回显本次使用的约束。
- 确认后：创建 `roster`，锁定飞机，状态 `LOCKED`；其他班次（M3：其他玩家）不可再抽到这架飞机。
- 班表窗口按用户设置（默认 24h）；到期未开始 → `EXPIRED`，释放飞机，记一次失约。
- 约束保存到 `roster.constraints_json`，便于审计与重抽复现；重抽可带新约束。
- 首段开始前可重抽，无冷却/费用/次数限制（见 C-05）；首段开始后班表 `IN_PROGRESS`，不可换机、不可改航段顺序。
- **首段开始后不设总任务时限**：只要未飞完，班表保持 `IN_PROGRESS`，不会自动过期；只能飞完或被取消。

### C-05 重抽与取消（MVP，MUST）

- 首段开始前允许重抽：
  - **唯一条件：`roster.status=LOCKED` 且首段未开始**；
  - 无冷却、无次数上限、无重抽费；
  - 重抽后旧班表 `CANCELLED`，飞机立即释放，可马上再抽；
  - 重抽可带新的软约束参数，按新参数重新抽；
  - 重抽不计失约、不影响抽班优先级。
- 取消班表：
  - 飞行员本人、ADMIN、DISPATCHER 均可取消。
  - 首段前：飞行员本人取消记一次失约（仅计数，不收费）；管理/签派取消不计。
  - 首段后：剩余航段 `CANCELLED`，飞机留在当前位置；飞行员本人收 $5,000，管理/签派不收；已飞航段正常结算。
- 首段开始后不可重抽；单段航班中止按备降/取消规则结算。
- 首段开始后无总任务时限：只要未飞完，班表保持 `IN_PROGRESS`，不会自动过期；只能飞完或被取消。
- 所有操作写审计日志；客户端只显示「是否可重抽」，不显示次数/冷却/费用。

### C-06 自由飞行（MVP，MUST）

- 不抽班表，直接选择：
  - 一架状态为 `ACTIVE` 且未被锁定/未在飞的飞机；
  - 一个航班实例（可选，也可自定 dep/arr + 时间）。
- 约束：
  - 飞机当前位置必须等于出发机场；
  - 机型满足航班的机型要求（或管理员放开）；
  - 自定航线的距离/机型必须在飞机航程内。
- 确认后创建短期锁（默认 30min，可续期），防止他人同时使用；开始飞行后锁转为 `IN_FLIGHT`。
- 自由飞行同样生成配载、结算、更新飞机位置与状态。
- 若飞机被班表锁定，不能自由飞行；反之亦然。

### C-07 配载与收益（MVP，MUST）

- 航班开始前，服务端按「航班 + 机型 + 时间 + 机场 + 随机种子」生成配载：
  - 旅客总数、按 `cabin_config` 的 F/J/W/Y 分布、货物 kg、邮件 kg；
  - 业载、零油重量、起飞重量、燃油重量；
  - 预计收入、各项成本、预计利润。
- 机型角色：`AIRLINER` / `BIZJET` / `VIP` / `CARGO` / `COMBI`；`BIZJET` 走整机包机费，不套用干线客座率；`VIP` 无商业收入；`CARGO` 只算货邮。
- 客户端展示配载单，允许在允许范围内调整（P1：减载/加货），MVP 只读。
- 配载在航班开始时固化；飞行中不随机变化；结算时按实际完成情况计算。
- 收益预估必须标注「预估」，最终以结算为准。

### C-08 飞行执行与上传（MVP，MUST）

- 流程：`领取航班 → 开始飞行 → SimLink 采集 → 落地 → 结束飞行 → 上传 → 结算`。
- 开始飞行时校验：班表/锁有效、飞机位置、机型、时间窗口；服务端返回 `flight_session_id` 与配载。
- 飞行中：每 30–60s 批量上传遥测；断线时本地排队，恢复后按序补传。
- 结束飞行时上传：轨迹摘要、事件、落地指标、油量、block time、实际起降。
- 服务端校验：
  - 轨迹连续性、距离/时间合理性、速度包线；
  - sim rate、暂停占比、瞬移；
  - 起降机场与航班一致；
  - 油量变化合理。
- 校验结果：`VALID` / `SUSPECT` / `INVALID`；`SUSPECT` 按公司 `settlement_policy` 处理：`ACCEPT` / `WEIGHTED` / `REVIEW` / `REJECT`；`INVALID` 不结算并记录。
- 客户端显示结算明细：收入、燃油、起降费、地面服务、机组、维护、租赁、penalty、净利润；`HELD` 显示待复核，`REJECT` 显示收入 0 与成本处理方式。

### C-09 我的（MVP，MUST）

- 我的班表、我的航班、我的飞行记录、我的账本（飞行员分成/工资，P1）。
- 个人统计：小时、航班数、准点率、平均落地、最大 G、收入贡献。
- 通知：班表到期提醒、航班变更、结算完成、公司公告。

## 5. 联机模式 · 服务端（Company Server，M3）

### S-01 飞机配置（MVP，MUST）

- 导入/导出：JSON 或 CSV；提供机型模板初始包（可复用 `aircrafts.json`）。

### S-02 航点与导航数据配置（MVP，MUST）

  - 自定义航点（名称、坐标、类型、备注）；
  - 公司航路（dep/arr、航路串、SID/STAR、巡航高度、最低机型、备注）；
  - 禁飞/限制区（可选，P1）。
- 航点校验：ident 唯一、坐标合法、与 navdata 不冲突时给警告。
- 版本管理：navdata 升级后保留旧版本，航班记录引用当时的 AIRAC。

### S-03 航线与班期（MVP，MUST）

> 这是原始需求缺失、但公司模式必需的一层。

- **航线 Route**：`dep/arr`、默认航路、距离、预计航时、最低机型类别、是否启用。
- **班期模板 Schedule**：航班号、航线、起飞本地时刻、星期几、有效日期、机型要求、过站时间。
- **航班实例 Flight Instance**：服务端每日（或手动）按模板生成未来 7 天的实例；含计划起降 UTC、状态、可用飞机。
- 支持 CSV 导入真实/自定义班期；支持批量复制、停用、删除。
- 航班号唯一性校验：同一公司同一天不重复。
- 时区：模板用基地/机场本地时刻，生成时换算 UTC；DST 由机场时区库处理。

### S-04 经济参数（MVP，MUST）

- 公司初始资金、货币（默认 USD）、基地机场、呼号前缀。
- 需求参数：各机场规模权重、距离衰减、时段系数、星期系数、季节系数、随机波动范围。
- 票价参数：经济/商务基础价、每海里价、机场等级系数。
- 成本参数：燃油单价（可按机场覆盖）、起降费/吨、地面服务/客、货运/吨、机组/小时、维护/小时、租赁/天、停机/小时。
- 惩罚参数：失约、取消、坠机、超时、备降、偏离航路。
- 所有参数在**网页管理端**修改（见 §6），修改写审计日志；航班结算使用**航班开始时快照**，避免中途改价。

### S-05 用户与权限（MVP，MUST）

- 公司创建、邀请码、加入/退出。
- 角色：`ADMIN / DISPATCHER(P1) / PILOT`。
- 管理员：配置、用户管理、全公司数据、强制释放锁定。
- 飞行员：自己的班表/航班/账本；可看公司公开数据。
- 密码 Argon2id；登录失败限流；token 过期与刷新；可选 2FA（P2）。
- 审计日志：谁在何时改了什么配置、释放了哪架飞机、结算了哪个航班。

### S-06 监控与审计（MVP，SHOULD）

- 实时看板：在线飞行员、在飞航班、飞机分布、今日收入/成本/利润。
- 航班列表：状态、异常标记、待复核。
- 飞机锁定列表：谁锁的、到期时间、可强制释放。
- 审计与错误日志：保留 90 天；支持导出。
- 健康检查：`/healthz`、数据库、航路引擎、navdata 版本。

## 6. 联机模式 · 网页管理端（Web Admin，M3）

> 详细页面、字段、权限、校验与验收见 [06-网页管理端.md](06-网页管理端.md)。

### W-01 访问与登录（MVP，MUST）

- 管理端是独立 SPA：浏览器加载静态前端，通过 `/api/v1/admin/*` 读写数据；**渲染由客户端完成，服务端只提供 JSON**。
- 管理员账号密码登录；服务端设置 HttpOnly Session Cookie + 返回 CSRF token；不返回 HTML/模板。
- 不公开注册；账号由 ADMIN 创建，或通过邀请码加入；PILOT 不进入管理端。
- 会话空闲 30min / 绝对 12h 过期；登录失败限流；`/admin` 支持 IP 白名单/VPN（部署配置）。
- 管理端与玩家 API 共用账号与 service 层，但会话机制不同（Cookie vs Bearer）。

### W-02 公司档案（MVP，MUST）

- 修改：公司名、ICAO、呼号前缀、基地机场、货币、初始资金调整（必须填原因）、显示时区。
- ICAO/呼号前缀唯一；基地/呼号变更只影响后续航班与抽班，不修改历史。
- 货币创建后只读（MVP 不做汇率）。

### W-03 经济参数（MVP，MUST）

- 分组：需求与载客、票价与收入、成本、惩罚与保险、经济防刷（同航线衰减、最低 block time）。异常处置见 W-10。
- 每个字段显示当前值、默认值、单位、范围、公式说明；字段级 + 跨字段校验。
- 流程：编辑（草稿仅浏览器本地）→ 预览影响（100 班合成）→ 发布；版本历史/对比/回滚。
- 发布使用乐观锁；并发修改返回冲突，不静默覆盖。
- 下一班生效；已开始/已结算航班使用 `economy_snapshot`（含 `settlement_policy`），不回溯。

### W-04 机队配置（MVP，MUST）

- 机型模板 CRUD（含 `role/variant/cabin_config/demand_profile`）；单机档案 CRUD；修改基地/当前位置/成本/状态；强制释放锁。
- 注册号唯一；机型/基地必须存在；MTOW 与跑道不匹配给警告。
- 修改当前位置、强制释放、退役等危险操作需二次确认 + 原因 + 审计。

### W-05 航点与航路（MVP，MUST）

- 自定义航点 CRUD；公司航路 CRUD；航路串调用 `aoc-route` 校验。
- navdata 版本查看与导入；导入异步、显示进度、失败回滚。
- `network.pkl` 与 navdata 的 AIRAC 不一致时，禁止生成航路并提示。

### W-06 航线与班期（MVP，MUST）

- 商业航线 CRUD；班期模板 CRUD；CSV 导入并输出错误行报告；手动生成未来 N 天航班实例。
- 航班号公司内唯一；时间按机场本地时区，生成时换算 UTC；DST 由时区库处理。
- 修改已被班表占用的航班实例时，必须提示冲突或禁止。

### W-07 用户与权限（MVP，MUST）

- 用户列表、创建、角色变更、禁用、重置密码；邀请码生成/作废。
- 权限：ADMIN 全量；DISPATCHER（P1）航线/班期/运行；PILOT 不进入管理端。
- 服务端逐路由校验，不依赖隐藏菜单；越权返回 403。

### W-08 运行监控与审计（MVP，SHOULD）

- 在飞/待复核航班、飞机锁定列表、强制释放、复核标记。
- 审计：登录、配置变更、危险操作；记录 before/after、操作人、IP、request_id；保留 90 天，可导出 CSV。
- 概览：余额、今日收入/成本/利润、在飞航班、在线飞行员、待复核、锁定飞机。

### W-09 非功能（MVP）

- 200 架飞机 / 5000 航班列表分页 ≤ 1s；概览 ≤ 2s；表单保存 ≤ 1s。
- Chrome/Edge 最近两个大版本；1280px 以上；中文默认；单位可切换。
- 客户端渲染 SPA（React + TypeScript + Vite）；服务端只提供 JSON API，不返回 HTML、不做 SSR/模板。
- 前端静态资源与 API 可独立部署；开发用 Vite dev server 代理 `/api`，生产用 Nginx/CDN。

### W-10 异常与结算策略（MVP，MUST）

- 公司级默认动作：`ACCEPT` / `REJECT` / `WEIGHTED` / `REVIEW`。
- 每个异常可单独配置：启用、动作、阈值、扣减比例/固定扣减、最高扣减；全局最低结算系数。
- 默认：数据缺口 `WEIGHTED`（每 10min -5%，最多 -30%，全局最低 factor 0.4）；时间加速 >8x `REJECT`；瞬移 `REJECT`；油量跳变/轨迹异常 `REVIEW`。
- `reject_cost_mode` 可配：`FULL`（全部成本）/ `DIRECT_ONLY`（燃油、起降、地面、空管）/ `NONE`（不扣，结算 `VOID`）。
- `review_advance_ratio` 可配：0–0.5，默认 0；`HELD` 时按预估利润预付，最终多退少补。
- `scope_mode` 可配：`COMPANY_ONLY`（默认，只用公司策略）/ `ALLOW_OVERRIDES`（允许覆盖）；覆盖类型为机型/单机/飞行员，优先级 飞行员 > 单机 > 机型 > 公司。
- 复核队列：`HELD` 航班在 M2 由客户端内「复核队列」处理，M3 起在网页端 `/admin/ops/review` 处理；可选 `ACCEPT` / `WEIGHTED` / `REJECT` + 原因；复核前不写最终账本，配置预付款时只写 `ADVANCE_PAYOUT`。
- 策略与经济参数一样版本化、预览、发布、回滚、审计；只影响后续航班，已开始航班用快照。
- 权限：ADMIN 改策略；DISPATCHER（P1）可复核不可改策略；PILOT 不可访问。
- 个人模式不应用该策略，只展示异常提示。

| A-16 | 数据缺口策略改为 `REVIEW` | 航班 `HELD`，不进账本；在复核队列确认后按 `ACCEPT`/`WEIGHTED` 结算 |
| A-17 | 策略从 `WEIGHTED` 改为 `REJECT` 并发布 | 下一班生效；历史结算不变；审计含 before/after |
| A-18 | `reject_cost_mode=NONE` 后瞬移 | 收入 0、成本 0，`settlement=VOID`，不写账本 |
| A-19 | `review_advance_ratio=0.3`，航班进入 `HELD` | 写 `ADVANCE_PAYOUT`；最终结算多退少补 |
| A-20 | 飞行员覆盖数据缺口为 `ACCEPT` | 该飞行员航班正常结算；其他飞行员仍按公司默认 |
